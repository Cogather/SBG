# BrowserGateway 数据管理模块设计说明书

## 1. 概述

### 1.1 模块定位
数据管理模块是BrowserGateway系统的核心业务模块，负责统一管理用户数据和文件存储操作。模块通过`IFileStorage`接口对外提供服务，由`FileStorageServiceImpl`实现，提供文件上传、下载、删除、查询等基础功能，以及用户数据的专用上传下载功能。

### 1.2 设计目标
- **文件存储管理**：提供统一的文件存储接口，支持S3兼容存储服务
- **用户数据管理**：支持用户数据的下载、上传、删除，包含压缩和脱敏处理
- **批量操作支持**：支持批量文件上传和删除操作
- **文件元数据查询**：支持文件存在性检查、文件大小查询、文件访问URL生成
- **存储服务抽象**：通过CSE服务注册中心动态获取存储服务端点，实现服务发现

### 2.4 数据存储

数据管理模块通过HTTP API与S3兼容存储服务交互，不直接管理本地数据存储。存储路径遵循以下规则：

- **远程路径格式**: `{bucket}/{path1}/{path2}/.../{filename}`
  - 解析规则：第一个路径段作为bucket名称，后续路径段转换为文件名（用下划线连接）
  - 示例：`userdata/user123/userdata.json.zst` → bucket=`userdata`, name=`user123_userdata.json.zst`

- **用户数据路径**:
  - 本地路径: `{userDataPath}/{userId}/userdata.json`
  - 本地压缩: `{userDataPath}/{userId}/userdata.json.zst`
  - 远程路径: `userdata/{userId}/userdata.json.zst`

#### 3.2.2 uploadFile(String localFilePath, String remoteUrl) 方法

**功能**: 上传本地文件到远程存储

**执行流程**:
```
1. 解析远程路径: parseS3Url(remoteUrl) -> S3Path对象
   - bucket = 路径第一个段
   - name = 后续路径段用下划线连接
2. 获取本地文件: Path.of(localFilePath).toFile()
3. 获取存储服务端点: cse.getReportEndpoint()
4. 构建上传URL: "http://" + endpoint + String.format(url, bucket, name)
5. 创建MultipartEntityBuilder，添加文件实体:
   - 调用addBinaryBody("file", file, ContentType.DEFAULT_BINARY, file.getName())
   - 文件字段名: "file"
   - ContentType: DEFAULT_BINARY（二进制类型）
   - 文件名: file.getName()（使用本地文件名）
6. 创建HttpPost请求，设置文件实体
7. 执行HTTP请求:
   - 响应码200: 打印info日志"upload {remoteUrl} success"
   - 响应码非200: 调用dealFileHttpError()处理错误
8. 异常处理: catch IOException，打印error日志"upload {s3Path} failed"
```

**异常处理**: catch IOException，打印error日志，不抛出异常

#### 3.2.3 downloadFile(String localFilePath, String remoteUrl) 方法

**功能**: 从远程存储下载文件到本地

**执行流程**:
```
1. 解析远程路径: parseS3Url(remoteUrl) -> S3Path对象
2. 获取存储服务端点: cse.getReportEndpoint()
3. 构建下载URL: "http://" + endpoint + String.format(url, bucket, name)
4. 创建HttpGet请求
5. 执行HTTP请求:
   - 响应码200且实体不为null:
     a. 使用try-with-resources创建FileOutputStream: try (FileOutputStream out = new FileOutputStream(localFilePath))
     b. 调用entity.writeTo(out)写入文件流
   - 响应码非200或实体为null:
     a. 调用dealFileHttpError()处理错误
     b. 消费响应实体EntityUtils.consume()
6. 异常处理: catch IOException，打印error日志"download {s3Path} failed"
```

**异常处理**: catch IOException，打印error日志，不抛出异常

#### 3.2.4 deleteFile(String remoteUrl) 方法

#### 3.2.5 exist(String remoteUrl) 方法

**功能**: 检查远程文件是否存在

**返回值**: `boolean` - 文件存在返回true，不存在或异常返回false

**执行流程**:
```
1. 解析远程路径: parseS3Url(remoteUrl) -> S3Path对象
2. 获取存储服务端点: cse.getReportEndpoint()
3. 构建存在性检查URL: "http://" + endpoint + String.format(existUrl, bucket, name)
4. 创建HttpGet请求
5. 执行HTTP请求:
   - 响应码200: 返回true
   - 响应码404: 返回false（文件不存在，不记录错误）
   - 响应码其他: 调用dealFileHttpError()处理错误，返回false
6. 异常处理: catch IOException，打印error日志"delete {s3Path} failed"（注意：此处日志内容有误，应为"exist"而非"delete"），返回false
```

**异常处理**: catch IOException，打印error日志，返回false

#### 3.2.6 getFileSize(String path) 方法

**功能**: 获取远程文件大小

**返回值**: `long` - 文件大小（字节），文件不存在或异常返回-1

**执行流程**:
```
1. 解析远程路径: parseS3Url(path) -> S3Path对象
2. 获取存储服务端点: cse.getReportEndpoint()
3. 构建文件大小查询URL: "http://" + endpoint + String.format(sizeUrl, bucket, name)
4. 创建HttpGet请求
5. 执行HTTP请求:
   - 响应码200且实体不为null:
     a. 读取响应体: EntityUtils.toString(entity)
     b. 解析为Long: Long.parseLong(content.trim())
     c. 返回文件大小
   - 响应码非200或解析失败: 调用dealFileHttpError()，返回-1
6. 处理返回结果: return result != null ? result : -1L（处理null情况）
7. 异常处理: catch IOException，打印error日志"get file size failed for path: {path}"，返回-1
```

**异常处理**: catch IOException或解析异常，打印error日志，返回-1

#### 3.2.8 downloadUserData(String userDataPath, String userId, String serverAddr) 方法

**功能**: 下载用户数据（包含解压处理）

**参数说明**:
- `userDataPath`: 用户数据目录
- `userId`: 用户ID
- `serverAddr`: 服务器地址（**注意：当前实现中此参数未使用**）

**返回值**: `String` - 本地用户数据文件路径

**执行流程**:
```
1. 打印info日志"Downloading Chrome user data for user {userId}"
2. 计算本地路径: FileUtil.file(userDataPath, userId, "userdata.json")
3. 计算远程路径: Paths.get("userdata", userId, "userdata.json.zst").toString()
4. 调用exist(remoteURL)检查远程文件是否存在
   - 不存在: 打印info日志，返回本地路径（使用空的本地数据）
5. 检查本地父目录是否存在
   - 不存在: FileUtil.mkdir()创建目录，FileUtil.touch()创建文件
6. 计算本地压缩文件路径: {userDataPath}/{userId}/userdata.json.zst
7. 调用downloadFile(localZip, remoteURL)下载压缩文件
8. 调用ZstdUtil.decompressJson(localZip, localUserData)解压
9. 如果本地压缩文件存在，删除: FileUtil.del(localZip)
10. 返回本地用户数据文件路径
```

**异常处理**: catch所有异常，打印error日志，返回本地路径（降级处理）

#### 3.2.9 uploadUserData(String userDataPath, String userId, String serverAddr) 方法

**功能**: 上传用户数据（包含脱敏和压缩处理）

**参数说明**:
- `userDataPath`: 用户数据目录
- `userId`: 用户ID
- `serverAddr`: 服务器地址（**注意：当前实现中此参数未使用**）

**返回值**: `boolean` - 上传成功返回true，失败返回false

**执行流程**:
```
1. 打印info日志"Uploading Chrome user data for user {userId}"
2. 获取本地文件路径: FileUtil.file(userDataPath, userId, "userdata.json")
3. 检查本地文件是否存在
   - 不存在: 打印warn日志，返回false
4. 调用UserdataSlimmer.slimInplace(localUserData) - 原地脱敏处理
   - 过滤过期Cookie
   - 仅保留登录凭证相关Cookie
   - 过滤localStorage，仅保留登录和验证相关条目
5. 压缩: 计算压缩文件路径 {userDataPath}/{userId}/userdata.json.zst
6. 调用ZstdUtil.compressJson(localUserData, localZip)压缩
   - 压缩失败: 打印error日志，返回false
7. 计算远程路径: Paths.get("userdata", userId, "userdata.json.zst").toString()
8. 记录上传开始时间: startUpload = System.currentTimeMillis()
9. 如果远程文件已存在，先删除: exist(remoteURL) -> deleteFile(remoteURL)
10. 调用uploadFile(localZip, remoteURL)上传
11. 打印info日志，包含耗时: "upload userdata to remote storage end, cost {} ms"
12. 如果本地压缩文件存在，删除: FileUtil.del(localZip)
13. 返回true
```

**异常处理**: catch所有异常，打印error日志，返回false

#### 3.2.10 batchUpload(Map<String, String> fileMap) 方法

**功能**: 批量上传文件

**参数**: `fileMap` - 文件路径映射 {本地路径: 远程路径}

**返回值**: `Map<String, String>` - 上传结果 {文件路径: 访问URL或远程路径}

**执行流程**:
```
1. 创建结果Map: new HashMap<>()
2. 遍历fileMap的每个entry:
   a. 获取localPath和remotePath
   b. try-catch包裹:
      - 调用uploadFile(localPath, remotePath)
      - 将结果放入result: result.put(localPath, remotePath)
      - 注意：当前uploadFile方法没有返回URL，这里先返回远程路径
      - 如果需要返回访问URL，需要修改uploadFile方法或调用getFileUrl
      - 异常: 打印error日志"batch upload failed for localPath: {}, remotePath: {}", result.put(localPath, null)
3. 返回result
```

**异常处理**: 每个文件独立处理，单个文件失败不影响其他文件

#### 3.2.11 batchDelete(Set<String> paths) 方法

**功能**: 批量删除文件

**参数**: `paths` - 文件路径集合

**返回值**: `Map<String, Boolean>` - 删除结果 {文件路径: 是否成功}

**执行流程**:
```
1. 创建结果Map: new HashMap<>()
2. 遍历paths集合:
   a. try-catch包裹:
      - 调用deleteFile(path)
      - 将结果放入result: result.put(path, true)
      - 异常: 打印error日志，result.put(path, false)
3. 返回result
```

**异常处理**: 每个文件独立处理，单个文件失败不影响其他文件

#### 3.2.12 parseS3Url(String url) 私有方法

**功能**: 解析S3路径格式的URL

**返回值**: `S3Path` - 包含bucket和name的内部类对象

**执行流程**:
```
1. 使用Paths.get(url)解析路径
2. 提取bucket: path.getName(0).toString()（第一个路径段）
3. 提取name: path.subpath(1, path.getNameCount()).toString().replace("/", "_")
   - 将除第一个标识bucket之后的路径转换为一个文件名（用下划线连接）
4. 返回new S3Path(bucketName, name)
```

**示例**:
- 输入: `"userdata/user123/userdata.json.zst"`
- 输出: `S3Path(bucket="userdata", name="user123_userdata.json.zst")`

#### 3.2.13 dealFileHttpError(String method, S3Path file, ClassicHttpResponse response) 私有方法

**功能**: 统一处理文件操作HTTP错误

```
2. 异常处理: catch所有异常，打印error日志: "{method} failed, file:{file}, http status:{code}"
```

#### 3.5.2 getReportEndpoint() 方法

**功能**: 从CSE服务注册中心获取存储服务端点（随机选择一个可用端点）

**返回值**: `String` - 端点地址（格式: IP:Port），失败返回空字符串

**执行流程**:
```
1. 检查serviceManagementAdapter是否为null
   - 为null: 打印warn日志，返回""
2. 查询服务实例: serviceManagementAdapter.findServiceInstances("0", "gids", "0+")
3. 如果实例列表为空: 返回""
4. 创建端点集合: HashSet<String> endpoints
5. 遍历服务实例:
   a. 如果实例状态不是UP: 跳过
   b. 遍历实例的endpoints列表:
      - 调用extractIPPort(endpoint)提取IP:Port
      - 如果提取成功，添加到endpoints集合
6. 如果endpoints为空: 返回""
7. 随机选择一个端点: endpoints.toArray()[random.nextInt(endpoints.size())]
8. 返回端点字符串
```

**异常处理**: 接口内部处理异常，可能返回空字符串

#### 3.5.3 extractIPPort(String endpoint) 私有方法

**功能**: 从端点URL中提取IP和端口

**返回值**: `String` - IP:Port格式，失败返回null

**执行流程**:
```
1. try-catch包裹:
   a. 解析URI: new URI(endpoint)
   b. 提取host和port: uri.getHost() + ":" + uri.getPort()
   c. 返回IP:Port字符串
2. 异常处理: catch URISyntaxException，打印error日志，返回null
```

## 7. 关键流程

### 7.1 用户数据下载完整流程

```
调用方 -> FileStorageServiceImpl.downloadUserData(userDataPath, userId, serverAddr)
  -> 计算本地路径: {userDataPath}/{userId}/userdata.json
  -> 计算远程路径: userdata/{userId}/userdata.json.zst
  -> exist(remoteURL) 检查远程文件是否存在
    -> ICse.getReportEndpoint() 获取存储服务端点
    -> HTTP GET /file/v1/{bucket}/{name}/exist
    -> 不存在: 返回本地路径（使用空数据）
  -> 创建本地目录（如果不存在）
  -> downloadFile(localZip, remoteURL) 下载压缩文件
    -> ICse.getReportEndpoint() 获取存储服务端点
    -> HTTP GET /file/v1/{bucket}/{name}
    -> 写入本地文件: {userDataPath}/{userId}/userdata.json.zst
  -> ZstdUtil.decompressJson(localZip, localUserData) 解压
    -> 读取.zst文件
    -> Zstd解压
    -> 写入.json文件
  -> 删除本地压缩文件
  -> 返回本地用户数据文件路径
```

### 7.2 用户数据上传完整流程

```
调用方 -> FileStorageServiceImpl.uploadUserData(userDataPath, userId, serverAddr)
  -> 获取本地文件: {userDataPath}/{userId}/userdata.json
  -> 检查本地文件是否存在
    -> 不存在: 返回false
  -> UserdataSlimmer.slimInplace(localUserData) 数据脱敏
    -> 过滤过期Cookie
    -> 仅保留登录凭证相关Cookie
    -> 过滤localStorage，仅保留登录/验证相关条目
  -> ZstdUtil.compressJson(localUserData, localZip) 压缩
    -> 读取.json文件
    -> Zstd压缩（级别6）
    -> 写入.zst文件
    -> 压缩失败: 返回false
  -> 计算远程路径: userdata/{userId}/userdata.json.zst
  -> exist(remoteURL) 检查远程文件是否存在
    -> 存在: deleteFile(remoteURL) 先删除旧文件
  -> uploadFile(localZip, remoteURL) 上传
    -> ICse.getReportEndpoint() 获取存储服务端点
    -> HTTP POST /file/v1/{bucket}/{name}
    -> MultipartEntityBuilder添加文件实体
    -> 上传到存储服务
  -> 删除本地压缩文件
  -> 返回true
```

### 7.3 文件上传流程

```
调用方 -> FileStorageServiceImpl.uploadFile(localPath, remotePath)
  -> parseS3Url(remotePath) 解析路径
    -> bucket = 路径第一个段
    -> name = 后续路径段用下划线连接
  -> ICse.getReportEndpoint() 获取存储服务端点
  -> 构建URL: http://{endpoint}/file/v1/{bucket}/{name}
  -> 创建MultipartEntityBuilder，添加文件实体
  -> HTTP POST请求
  -> 响应码200: 成功
  -> 响应码非200: dealFileHttpError()处理错误
```

### 7.4 文件下载流程

```
调用方 -> FileStorageServiceImpl.downloadFile(localPath, remotePath)
  -> parseS3Url(remotePath) 解析路径
  -> ICse.getReportEndpoint() 获取存储服务端点
  -> 构建URL: http://{endpoint}/file/v1/{bucket}/{name}
  -> HTTP GET请求
  -> 响应码200且实体不为null:
    -> 创建FileOutputStream
    -> entity.writeTo(out) 写入本地文件
  -> 响应码非200: dealFileHttpError()处理错误
```

### 7.5 CSE端点获取流程

```
调用方 -> CseImpl.getReportEndpoint()
  -> serviceManagementAdapter.findServiceInstances("0", "gids", "0+")
    -> 查询CSE服务注册中心
    -> 返回服务实例列表
  -> 过滤UP状态的实例
  -> 遍历实例endpoints，提取IP:Port
    -> extractIPPort(endpoint)
      -> 解析URI
      -> 提取host和port
  -> 随机选择一个端点
  -> 返回端点字符串（格式: IP:Port）
```

## 9. 异常处理

### 9.1 FileStorageServiceImpl层

#### 9.1.1 基础文件操作（uploadFile/downloadFile/deleteFile）

- **异常类型**: IOException
- **处理方式**: catch异常，打印error日志，不抛出异常
- **影响**: 操作失败但不影响调用方继续执行

#### 9.1.2 文件查询操作（exist/getFileSize/getFileUrl）

- **异常类型**: IOException、解析异常
- **处理方式**: 
  - exist(): catch异常，返回false
  - getFileSize(): catch异常，返回-1
  - getFileUrl(): catch异常，返回null
- **影响**: 降级处理，返回默认值

#### 9.1.3 用户数据操作（downloadUserData/uploadUserData）

- **异常类型**: 所有异常（Exception）
- **处理方式**: 
  - downloadUserData(): catch异常，打印error日志，返回本地路径（降级处理）
  - uploadUserData(): catch异常，打印error日志，返回false
- **影响**: 降级处理，确保系统稳定性

#### 9.1.4 批量操作（batchUpload/batchDelete）

- **异常类型**: Exception
- **处理方式**: 每个文件独立try-catch，单个文件失败不影响其他文件
- **影响**: 部分失败不影响整体操作

### 9.2 CseImpl层

#### 9.2.1 getReportEndpoint()

- **异常类型**: 服务查询异常、URI解析异常
- **处理方式**: 
  - serviceManagementAdapter为null: 返回空字符串
  - 服务实例为空: 返回空字符串
  - URI解析失败: 打印error日志，跳过该端点
- **影响**: 降级处理，返回空字符串时文件操作会失败

### 9.3 错误响应处理

#### 9.3.1 dealFileHttpError()

- **功能**: 统一处理HTTP错误响应
- **处理流程**:
  1. 尝试解析响应体为BaseResponse
  2. 打印error日志，包含method、file、code、message
  3. 如果解析失败，打印HTTP状态码
- **异常处理**: catch所有异常，确保错误处理不会抛出异常

## 11. 路径解析规则

### 11.1 S3路径格式

**输入格式**: `{bucket}/{path1}/{path2}/.../{filename}`

**解析规则**:
1. 第一个路径段作为bucket名称
2. 后续所有路径段转换为文件名，用下划线（_）连接

**示例**:
- 输入: `"userdata/user123/userdata.json.zst"`
- 解析结果: bucket=`"userdata"`, name=`"user123_userdata.json.zst"`

- 输入: `"plugins/extension/keys/control.js"`
- 解析结果: bucket=`"plugins"`, name=`"extension_keys_control.js"`

### 11.2 用户数据路径规范

**本地路径**:
- 用户数据文件: `{userDataPath}/{userId}/userdata.json`
- 压缩文件: `{userDataPath}/{userId}/userdata.json.zst`

**远程路径**:
- 压缩文件: `userdata/{userId}/userdata.json.zst`

**路径计算**:
- 使用`Paths.get()`构建路径，确保跨平台兼容性
- 使用`FileUtil.file()`构建本地文件路径

## 12. API端点说明

### 12.1 存储服务API端点

所有API端点基于以下格式：
- **基础URL**: `http://{endpoint}/file/v1/{bucket}/{name}`
- **endpoint**: 通过`ICse.getReportEndpoint()`动态获取

### 12.2 支持的HTTP操作

| 操作 | HTTP方法 | URL | 说明 |
|------|---------|-----|------|
| 上传文件 | POST | `/file/v1/{bucket}/{name}` | Multipart/form-data，文件字段名"file"，ContentType为DEFAULT_BINARY |
| 下载文件 | GET | `/file/v1/{bucket}/{name}` | 返回文件流 |
| 删除文件 | DELETE | `/file/v1/{bucket}/{name}` | 删除指定文件 |
| 检查存在 | GET | `/file/v1/{bucket}/{name}/exist` | 返回200存在，404不存在 |
| 获取大小 | GET | `/file/v1/{bucket}/{name}/size` | 返回文件大小（字节，纯文本） |
| 获取URL | GET | `/file/v1/{bucket}/{name}/url?expire={seconds}` | 返回文件访问URL（纯文本） |

### 12.3 响应格式

**成功响应**:
- 状态码: 200
- 文件操作: 无响应体或文件流
- 查询操作: 返回纯文本结果（大小、URL）或JSON（存在性）

**错误响应**:
- 状态码: 非200（常见404、500等）
- 响应体: JSON格式 `{"code": 错误码, "msg": "错误消息"}`
