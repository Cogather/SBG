# 数据管理模块 - 模块间接口契约文档

## 1. 概述

本文档定义了数据管理模块与其他模块之间的接口契约。数据管理模块是BGW系统的核心模块，负责统一管理用户数据和文件存储操作，提供文件上传、下载、删除、查询等基础功能，以及用户数据的专用上传下载功能。对外通过`IFileStorage`接口提供服务。本文档确保模块间的交互规范、明确、无歧义，依据本文档和设计说明书可100%复现数据管理模块的全部功能代码。

## 2. 模块依赖关系

```
数据管理模块 (service.IFileStorage)
│
├── [对外提供] IFileStorage 接口
│   ├── 调用方: 浏览器管理模块 (service.impl.UserData)
│   │   ├── exist(path) - 检查远程用户数据是否存在
│   │   ├── downloadFile(local, remote) - 下载用户数据压缩文件
│   │   ├── uploadFile(local, remote) - 上传用户数据压缩文件
│   │   └── deleteFile(path) - 删除远程用户数据
│   ├── 调用方: 插件管理模块 (service.impl.HWCallbackImpl)
│   │   ├── exist(path) - 检查远程文件是否存在
│   │   ├── downloadFile(local, remote) - SDK下载文件
│   │   ├── uploadFile(local, remote) - SDK上传文件
│   │   └── deleteFile(path) - 删除远程文件
│   └── 调用方: 扩展管理服务 (service.ExtensionManageService)
│       └── downloadFile(local, remote) - 下载插件包
│
└── [依赖] 外部模块接口
    ├── CSE服务接口 (service.ICse)
    └── 服务管理适配器 (adapter.interfaces.ServiceManagementAdapter)
```

## 3. 对外提供的接口契约

### 3.1 IFileStorage 接口

#### 3.1.1 接口描述
文件存储服务的核心接口，提供文件上传、下载、删除、查询等基础功能，以及用户数据的专用上传下载功能。由`FileStorageServiceImpl`实现，注册为Spring Bean（`@Service`）。

#### 3.1.2 接口定义
```java
package com.huawei.browsergateway.service;

import java.util.Map;
import java.util.Set;

/**
 * 文件存储服务接口，统一管理用户数据和文件操作
 */
public interface IFileStorage {
    
    /**
     * 上传文件到存储
     *
     * 功能: 将本地文件上传到S3兼容存储服务
     *
     * 调用方:
     *   - UserData.upload() - 上传用户数据压缩文件
     *   - HWCallbackImpl.uploadFile() - SDK上传文件
     *
     * 调用时机:
     *   - 浏览器关闭时上传用户数据
     *   - SDK需要上传文件到远程存储时
     *
     * @param localPath 本地文件路径（绝对路径）
     * @param remotePath 远程存储路径（S3路径格式: bucket/path/to/file）
     *   - 路径格式: 第一个路径段作为bucket名称，后续路径段转换为文件名（用下划线连接）
     *   - 示例: "userdata/user123/file.json" → bucket="userdata", name="user123_file.json"
     *
     * 接口行为:
     *   - 将本地文件上传到S3兼容存储服务
     *   - 如果文件已存在，会被覆盖
     *   - 上传失败时不会抛出异常，但会记录错误日志
     *
     * 异常处理: 内部处理所有异常，不向上抛出，调用方无需处理异常
     */
    void uploadFile(String localPath, String remotePath);
    
    /**
     * 下载文件到本地
     *
     * 功能: 从S3兼容存储服务下载文件到本地
     *
     * 调用方:
     *   - UserData.download() - 下载用户数据压缩文件
     *   - HWCallbackImpl.getFile() - SDK下载文件
     *   - ExtensionManageService.downPlugin() - 下载插件包
     *
     * 调用时机:
     *   - 浏览器创建时下载用户数据
     *   - SDK需要从远程存储下载文件时
     *   - 加载插件时下载插件包
     *
     * @param localPath 本地保存路径（绝对路径，如果文件已存在会被覆盖）
     * @param remotePath 远程文件路径（S3路径格式，同uploadFile的路径格式）
     *
     * 接口行为:
     *   - 从S3兼容存储服务下载文件到本地
     *   - 如果本地文件已存在，会被覆盖
     *   - 下载失败时不会抛出异常，但会记录错误日志
     *
     * 异常处理: 内部处理所有异常，不向上抛出，调用方无需处理异常
     */
    void downloadFile(String localPath, String remotePath);
    
    /**
     * 删除文件
     *
     * 功能: 删除远程存储中的文件
     *
     * 调用方:
     *   - UserData.upload() - 上传前先删除已有文件
     *   - UserData.delete() - 删除用户远程数据
     *   - HWCallbackImpl.uploadFile() - 上传前先删除已有文件
     *
     * 调用时机:
     *   - 上传文件前删除旧文件
     *   - 删除用户数据时
     *
     * @param path 远程文件路径（S3路径格式，同uploadFile的路径格式）
     *
     * 接口行为:
     *   - 删除远程存储中的文件
     *   - 如果文件不存在，操作会失败但不会抛出异常
     *   - 删除失败时不会抛出异常，但会记录错误日志
     *
     * 异常处理: 内部处理所有异常，不向上抛出，调用方无需处理异常
     */
    void deleteFile(String path);
    
    /**
     * 检查文件是否存在
     *
     * 功能: 检查远程存储中的文件是否存在
     *
     * 调用方:
     *   - UserData.download() - 检查远程是否有用户数据
     *   - UserData.upload() - 上传前检查是否需要先删除
     *   - HWCallbackImpl.uploadFile() - 上传前检查是否需要先删除
     *
     * 调用时机:
     *   - 下载文件前检查是否存在
     *   - 上传文件前检查是否需要删除旧文件
     *
     * @param path 远程文件路径（S3路径格式，同uploadFile的路径格式）
     * @return boolean 文件存在返回true，不存在或异常返回false
     *
     * 接口行为:
     *   - 检查远程存储中的文件是否存在
     *   - 文件不存在时返回false（不视为错误）
     *   - 查询失败时返回false（降级处理）
     *
     * 异常处理: 内部处理所有异常，返回false，调用方无需处理异常
     */
    boolean exist(String path);
    
    /**
     * 获取文件大小
     *
     * 功能: 获取远程文件的大小（字节）
     *
     * 调用方: 外部查询文件大小
     *
     * @param path 远程文件路径（S3路径格式，同uploadFile的路径格式）
     * @return long 文件大小（字节），文件不存在或异常返回-1
     *
     * 接口行为:
     *   - 获取远程文件的大小（字节）
     *   - 文件不存在或查询失败时返回-1（降级处理）
     *
     * 异常处理: 内部处理所有异常，返回-1，调用方无需处理异常
     */
    long getFileSize(String path);
    
    /**
     * 获取文件访问URL
     *
     * 功能: 获取文件的临时访问URL（带过期时间）
     *
     * 调用方: 外部需要获取文件访问URL
     *
     * @param path 远程文件路径（S3路径格式，同uploadFile的路径格式）
     * @param expireSeconds 过期时间（秒）
     * @return String 文件访问URL，失败返回null
     *
     * 接口行为:
     *   - 获取文件的临时访问URL（带过期时间）
     *   - 生成的URL在指定秒数后过期
     *   - 获取失败时返回null（降级处理）
     *
     * 异常处理: 内部处理所有异常，返回null，调用方无需处理异常
     */
    String getFileUrl(String path, int expireSeconds);
    
    /**
     * 用户数据下载
     *
     * 功能: 下载用户数据并自动解压（包含完整的下载+解压流程）
     *
     * 调用方: 外部需要下载用户数据（当前实现中未被直接调用，UserData使用基础方法）
     *
     * @param userDataPath 用户数据目录
     * @param userId 用户ID（格式: {imei}_{imsi}）
     * @param serverAddr 服务器地址（注意：当前实现中此参数未使用）
     * @return String 本地用户数据文件路径
     *
     * 接口行为:
     *   - 下载用户数据并自动解压（包含完整的下载+解压流程）
     *   - 如果远程文件不存在，返回本地路径（使用空的本地数据）
     *   - 下载或解压失败时，返回本地路径（降级处理，不抛出异常）
     *
     * 异常处理: 内部处理所有异常，返回本地路径（降级处理），调用方无需处理异常
     */
    String downloadUserData(String userDataPath, String userId, String serverAddr);
    
    /**
     * 用户数据上传
     *
     * 功能: 上传用户数据并自动脱敏和压缩（包含完整的脱敏+压缩+上传流程）
     *
     * 调用方: 外部需要上传用户数据（当前实现中未被直接调用，UserData使用基础方法）
     *
     * @param userDataPath 用户数据目录
     * @param userId 用户ID（格式: {imei}_{imsi}）
     * @param serverAddr 服务器地址（注意：当前实现中此参数未使用）
     * @return boolean 上传成功返回true，失败返回false
     *
     * 接口行为:
     *   - 上传用户数据并自动脱敏和压缩（包含完整的脱敏+压缩+上传流程）
     *   - 如果本地文件不存在，返回false
     *   - 如果远程文件已存在，会先删除再上传
     *   - 上传失败时返回false（不抛出异常）
     *
     * 异常处理: 内部处理所有异常，返回false，调用方无需处理异常
     */
    boolean uploadUserData(String userDataPath, String userId, String serverAddr);
    
    /**
     * 批量文件上传
     *
     * 功能: 批量上传多个文件
     *
     * 调用方: 外部需要批量上传文件
     *
     * @param fileMap 文件路径映射 {本地路径: 远程路径}
     * @return Map<String, String> 上传结果 {文件路径: 访问URL或远程路径}
     *   - 成功: result.put(localPath, remotePath)
     *   - 失败: result.put(localPath, null)
     *
     * 接口行为:
     *   - 批量上传多个文件
     *   - 每个文件独立处理，单个文件失败不影响其他文件
     *   - 注意：当前返回的是远程路径，不是访问URL
     *
     * 异常处理: 每个文件独立处理异常，单个文件失败不影响其他文件，调用方无需处理异常
     */
    Map<String, String> batchUpload(Map<String, String> fileMap);
    
    /**
     * 批量文件删除
     *
     * 功能: 批量删除多个文件
     *
     * 调用方: 外部需要批量删除文件
     *
     * @param paths 文件路径集合
     * @return Map<String, Boolean> 删除结果 {文件路径: 是否成功}
     *   - 成功: result.put(path, true)
     *   - 失败: result.put(path, false)
     *
     * 接口行为:
     *   - 批量删除多个文件
     *   - 每个文件独立处理，单个文件失败不影响其他文件
     *
     * 异常处理: 每个文件独立处理异常，单个文件失败不影响其他文件，调用方无需处理异常
     */
    Map<String, Boolean> batchDelete(Set<String> paths);
}
```

## 4. 依赖的外部接口契约

### 4.1 CSE服务接口 (ICse)

#### 4.1.1 接口描述
提供CSE服务注册中心的端点地址获取功能，用于动态获取存储服务端点。

#### 4.1.2 使用的接口方法

```java
package com.huawei.browsergateway.service;

public interface ICse {
    /**
     * 获取CSE上报端点地址
     *
     * 调用方:
     *   - FileStorageServiceImpl的所有HTTP请求方法 - 获取存储服务端点
     *
     * 调用时机: 每次执行文件操作前获取存储服务端点
     *
     * @return String CSE端点地址（格式: IP:Port），失败返回空字符串
     *
     * 接口行为:
     *   - 从CSE服务注册中心动态获取存储服务端点
     *   - 随机选择一个可用端点返回（负载均衡）
     *   - 如果查询失败或没有可用端点，返回空字符串
     *
     * 异常处理: 接口内部处理异常，可能返回空字符串
     * 说明: 返回空字符串时，文件操作会失败（HTTP请求无法构建URL）
     */
    String getReportEndpoint();
}
```

#### 4.1.3 调用场景

| 方法 | 调用方 | 说明 |
|------|--------|------|
| getReportEndpoint() | FileStorageServiceImpl的所有方法 | 获取存储服务端点，用于构建HTTP请求URL |

## 5. 数据对象契约

### 5.1 S3路径解析规则

**路径格式**: `{bucket}/{path1}/{path2}/.../{filename}`

**解析规则**:
1. 第一个路径段作为bucket名称
2. 后续所有路径段转换为文件名，用下划线（_）连接

**示例**:
- 输入: `"userdata/user123/userdata.json.zst"`
- 解析结果: bucket=`"userdata"`, name=`"user123_userdata.json.zst"`

- 输入: `"plugins/extension/keys/control.js"`
- 解析结果: bucket=`"plugins"`, name=`"extension_keys_control.js"`

### 5.2 用户数据路径规范

**本地路径**:
- 用户数据文件: `{userDataPath}/{userId}/userdata.json`
- 压缩文件: `{userDataPath}/{userId}/userdata.json.zst`

**远程路径**:
- 压缩文件: `userdata/{userId}/userdata.json.zst`

### 5.3 BaseResponse 响应实体

**包路径**: `com.huawei.browsergateway.entity.BaseResponse`

| 字段名 | JSON属性名 | 类型 | 说明 |
|--------|-----------|------|------|
| code | code | int | 响应状态码 |
| msg | msg | String | 响应消息 |

**方法**:
- `getCode()`: 返回状态码
- `getMessage()`: 返回消息（映射到msg字段）

**使用场景**: HTTP错误响应解析，用于dealFileHttpError()方法

## 6. 异常处理契约

### 6.1 异常处理原则

数据管理模块的所有接口方法都采用**内部异常处理**策略，不会向上抛出异常，调用方无需进行异常处理。

### 6.2 异常处理方式

#### 6.2.1 基础文件操作（uploadFile/downloadFile/deleteFile）

- **异常处理**: 内部catch所有异常，不向上抛出
- **影响**: 操作失败但不影响调用方继续执行
- **调用方**: 无需try-catch，可直接调用

#### 6.2.2 查询操作（exist/getFileSize/getFileUrl）

- **异常处理**: 内部catch所有异常，返回默认值
  - exist(): 返回false
  - getFileSize(): 返回-1
  - getFileUrl(): 返回null
- **影响**: 降级处理，调用方需要检查返回值
- **调用方**: 需要检查返回值是否为默认值

#### 6.2.3 用户数据操作（downloadUserData/uploadUserData）

- **异常处理**: 内部catch所有异常，返回降级值
  - downloadUserData(): 返回本地路径（降级处理）
  - uploadUserData(): 返回false
- **影响**: 降级处理，确保系统稳定性
- **调用方**: 需要检查返回值

#### 6.2.4 批量操作（batchUpload/batchDelete）

- **异常处理**: 每个文件独立处理异常，单个文件失败不影响其他文件
- **影响**: 部分失败不影响整体操作
- **调用方**: 需要检查返回结果Map中的每个文件状态

## 7. 性能要求

### 7.1 响应时间要求

| 操作 | 响应时间要求 | 说明 |
|------|------------|------|
| exist() | < 1秒 | 文件存在性检查 |
| getFileSize() | < 1秒 | 文件大小查询 |
| getFileUrl() | < 1秒 | 文件URL生成 |
| uploadFile() | 取决于文件大小 | 文件上传，大文件可能较慢 |
| downloadFile() | 取决于文件大小 | 文件下载，大文件可能较慢 |
| deleteFile() | < 1秒 | 文件删除 |
| downloadUserData() | 取决于文件大小 | 包含下载+解压流程 |
| uploadUserData() | 取决于文件大小 | 包含脱敏+压缩+上传流程 |

### 7.2 并发要求

- **HTTP客户端连接池**: 最大100连接，每路由20连接
- **线程安全**: FileStorageServiceImpl为无状态服务，所有方法无共享状态，线程安全
- **CSE端点获取**: 每次请求独立获取，支持负载均衡

## 8. 数据流转路径

### 8.1 用户数据存储路径

```
本地路径: {workspace}/userdata/{userId}/userdata.json
本地压缩: {workspace}/userdata/{userId}/userdata.json.zst
远程路径: userdata/{userId}/userdata.json.zst
```

### 8.2 用户数据生命周期

```
创建浏览器:
  S3远程 --[downloadFile]--> 本地.zst --[decompressJson]--> 本地.json
  本地.json --> BrowserOptions.userdata

关闭浏览器:
  chromeDriver.saveUserdata() --> 本地.json
  本地.json --[slimInplace]--> 本地.json(裁剪后)
  本地.json --[compressJson]--> 本地.zst --[uploadFile]--> S3远程
  删除本地.zst

删除用户数据:
  删除本地.json
  deleteFile(S3远程.zst)
```

### 8.3 SDK文件存储路径

```
本地路径: {tmpPath}/{userId}/{fileName}
远程路径: clientDownload/{userId}/{fileName}
```

### 8.4 插件包存储路径

```
本地路径: {workspace}/tmp/{packageName}
远程路径: {bucket}/{packageName}
```

### 8.5 数据流转说明

数据管理模块通过HTTP API与S3兼容存储服务交互，所有文件操作都通过统一的存储服务API完成。存储服务端点通过CSE服务注册中心动态获取，支持负载均衡。

## 9. 存储服务API端点规范

### 9.1 API端点格式

所有API端点基于以下格式：
- **基础URL**: `http://{endpoint}/file/v1/{bucket}/{name}`
- **endpoint**: 通过`ICse.getReportEndpoint()`动态获取（格式: IP:Port）

### 9.2 支持的HTTP操作

| 操作 | HTTP方法 | URL | 请求格式 | 响应格式 |
|------|---------|-----|---------|---------|
| 上传文件 | POST | `/file/v1/{bucket}/{name}` | Multipart/form-data<br>字段名: "file"<br>ContentType: DEFAULT_BINARY | 200: 成功<br>非200: JSON错误响应 |
| 下载文件 | GET | `/file/v1/{bucket}/{name}` | - | 200: 文件流<br>非200: JSON错误响应 |
| 删除文件 | DELETE | `/file/v1/{bucket}/{name}` | - | 200: 成功<br>非200: JSON错误响应 |
| 检查存在 | GET | `/file/v1/{bucket}/{name}/exist` | - | 200: 存在<br>404: 不存在<br>其他: JSON错误响应 |
| 获取大小 | GET | `/file/v1/{bucket}/{name}/size` | - | 200: 文件大小（字节，纯文本）<br>非200: JSON错误响应 |
| 获取URL | GET | `/file/v1/{bucket}/{name}/url?expire={seconds}` | - | 200: 文件访问URL（纯文本）<br>非200: JSON错误响应 |

### 9.3 错误响应格式

**JSON格式**:
```json
{
    "code": 错误码,
    "msg": "错误消息"
}
```

**常见错误码**:
- 404: 文件不存在
- 500: 服务器内部错误
- 其他: 根据具体错误返回
