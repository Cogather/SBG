# BrowserGateway 远程通信模块设计说明书

## 1. 概述

### 1.1 模块定位
远程通信模块是BrowserGateway系统的核心业务模块，负责与远程服务（CSE服务注册中心）进行通信，提供用户绑定信息管理、浏览器实例创建协调、数据统计上报、事件上报等功能。模块通过`IRemote`接口对外提供服务，由`RemoteImpl`实现。

### 1.2 设计目标
- **用户绑定管理**：查询、更新、过期用户与浏览器实例的绑定关系
- **浏览器创建协调**：协调浏览器实例的创建，处理配置变更和状态检查
- **分布式锁管理**：通过LockManager提供用户级别的分布式锁，防止并发创建冲突
- **数据统计上报**：上报媒体流量、控制流量、会话信息到远程监控服务
- **事件上报**：上报服务器事件到远程服务
- **容错处理**：提供fallback机制，处理异常场景下的浏览器实例关闭

### 2.4 数据存储

远程通信模块使用内存级`ConcurrentHashMap`存储用户锁：

```java
private static final ConcurrentHashMap<String, ReentrantLock> lockMap = new ConcurrentHashMap<>();
```

- **Key**: userId（由IMEI和IMSI拼接生成，格式：`{imei}_{imsi}`）
- **Value**: ReentrantLock对象（用于用户级别的并发控制）

#### 3.2.4 createChrome(byte[] receivedControlPackets, InitBrowserRequest parsedParams, Consumer<Object> consumer) 方法

**功能**: 创建或复用浏览器实例，处理配置变更和状态检查

**执行流程**:
```
1. 生成userId: UserIdUtil.generateUserIdByImeiAndImsi(parsedParams.getImei(), parsedParams.getImsi())
2. 打印info日志: "create browser instance, userId:{}, parsed params: {}"
3. 获取用户锁: lockManager.getLock(userId)
4. try块:
   a. 尝试获取锁: lock.tryLock(LOCK_TIMEOUT_SECONDS, TimeUnit.SECONDS)
      - 超时：打印error日志，抛出RuntimeException("get lock timeout!")
   b. 获取现有实例: chromeSet.get(userId)
   c. 检查浏览器状态: checkBrowserStatus(userChrome, receivedControlPackets)
      - 返回状态：OPEN_ERROR / PAGE_CONTROL_ERROR / REOPEN / NORMAL
   d. 打印状态日志: "[pre open]" 或 "[user connect]" + "user:{} browser status: {}"
   e. 如果状态不是NORMAL:
      - 调用chromeSet.deleteForRestart(userId) - 删除实例（不断开连接）
      - 调用createInstance(parsedParams, receivedControlPackets) - 创建新实例
   f. 如果consumer为null（预打开场景）:
      - 直接返回（不执行后续登录和事件处理）
   g. 如果consumer不为null（用户连接场景）:
      - 调用userChrome.getMuenDriver().Login(receivedControlPackets) - Moon SDK登录
      - 调用userChrome.getMuenDriver().onControlTcpConnected() - 通知控制连接已建立
      - 调用consumer.accept(null) - 执行回调
      - 调用this.handleEvent(receivedControlPackets, userId) - 处理控制事件
      - 清除告警: alarm.clearAlarm(AlarmEnum.ALARM_300033.getAlarmId())
      - 清除告警: alarm.clearAlarm(AlarmEnum.ALARM_300031.getAlarmId())
5. catch块:
   a. 检查异常消息:
      - 包含"failed to create browsers": 发送告警ALARM_300033
      - 包含"failed to create user interface": 发送告警ALARM_300031
   b. 打印error日志: "login and start record failed, user: {}."
   c. 调用chromeSet.delete(userId) - 删除实例
6. finally块:
   a. 如果当前线程持有锁: lock.unlock()
   b. 移除锁: lockManager.removeLock(userId)
```

**异常处理**: 
- 锁超时：抛出RuntimeException
- 其他异常：catch后删除实例，发送告警

#### 3.2.14 私有方法 checkBrowserStatus(UserChrome userChrome, byte[] encodeParam)

**功能**: 检查浏览器实例状态，判断是否需要重新创建

**返回值**: `BrowserStatus` - OPEN_ERROR / PAGE_CONTROL_ERROR / REOPEN / NORMAL

**执行流程**:
```
1. 如果userChrome为null:
   - 返回BrowserStatus.OPEN_ERROR（需要创建）
2. 如果userChrome.getStatus() == BrowserStatus.PAGE_CONTROL_ERROR:
   - 返回BrowserStatus.PAGE_CONTROL_ERROR（需要重新创建）
3. 调用Moon SDK登录: userChrome.getMuenDriver().Login(encodeParam)
   - 返回配置JSON字符串
4. 解析配置: JSONUtil.toBean(result, ChromeParams.class) -> newConfig
5. 比较配置: equalsConfig(newConfig, userChrome.getChromeParams())
   - 如果配置相同: 返回BrowserStatus.NORMAL（无需重新创建）
   - 如果配置不同:
     a. 打印info日志: "user:{} instance already exists, but config changes, reopen. old config:{}, new config:{}."
     b. 返回BrowserStatus.REOPEN（需要重新创建）
```

#### 3.2.15 私有方法 createInstance(InitBrowserRequest param, byte[] encodeParam)

**功能**: 创建浏览器实例并初始化

**返回值**: `UserChrome` - 创建完成的浏览器实例

**执行流程**:
```
1. 记录开始时间: start = System.currentTimeMillis()
2. 创建浏览器实例: chromeSet.create(param) -> userChrome
   - 内部：创建UserChrome对象，下载用户数据，构建BrowserOptions
3. 调用Moon SDK登录: userChrome.getMuenDriver().Login(encodeParam)
   - 返回配置JSON字符串
4. 解析配置: JSONUtil.toBean(result, ChromeParams.class) -> chromeParams
5. 设置配置: userChrome.setChromeParams(chromeParams)
6. 计算扩展路径:
   a. 获取前缀: extensionPathPrefix = config.getExtensionPath()
   b. 获取相对路径: relativePath = chromeParams.getControlExtentionPath()
   c. 提取文件名: relativePath.substring(relativePath.lastIndexOf("/"))
   d. 拼接完整路径: extensionPath = extensionPathPrefix + 文件名
7. 创建录制配置: ChromeRecordConfig.from(param, chromeParams) -> recordConfig
8. 设置录制配置字段:
   - recordConfig.setCodecMode(config.getCodecMode())
   - recordConfig.setLimit(config.getContextLimit())
   - recordConfig.setControlExtensionPath(extensionPath)
9. 创建浏览器进程: userChrome.createBrowser(recordConfig)
   - 内部：设置视口、录制数据、浏览器类型、扩展路径等，创建ChromiumDriverProxy
10. 打印info日志: "create browser instance success, user:{}, use time:{} ms."
11. 返回userChrome
```

#### 3.2.16 私有方法 equalsConfig(ChromeParams newConfig, ChromeParams oldConfig)

**功能**: 比较两个ChromeParams配置是否相同

**返回值**: `boolean` - true表示配置相同，false表示配置不同

**执行流程**:
```
1. 如果newConfig或oldConfig为null，返回false
2. 比较以下字段（使用Objects.equals）:
   - controlExtentionPath
   - controlExtentionId
   - chromeHeight
   - chromeWidth
   - frameRate
   - sampleRate
   - channels
   - bitRite
3. 如果所有字段都相同，返回true；否则返回false
```

### 3.3 LockManager 锁管理器

**包路径**: `com.huawei.browsergateway.service.impl.LockManager`

**注解**: `@Component`

#### 3.3.1 字段定义

| 字段名 | 类型 | 修饰符 | 说明 |
|--------|------|--------|------|
| lockMap | `ConcurrentHashMap<String, ReentrantLock>` | static final | 用户锁映射表 |

#### 3.3.2 getLock(String userId) 方法

**功能**: 获取指定用户的锁对象（如果不存在则创建）

**执行流程**:
```
1. 调用lockMap.computeIfAbsent(userId, k -> new ReentrantLock())
   - 如果userId对应的锁不存在，创建新的ReentrantLock
   - 如果已存在，直接返回
2. 返回ReentrantLock对象
```

#### 3.3.3 removeLock(String userId) 方法

**功能**: 移除指定用户的锁对象

**执行流程**:
```
1. 调用lockMap.remove(userId)
   - 从映射表中移除该userId对应的锁
```

## 7. 关键流程

### 7.1 创建浏览器实例完整流程

```
客户端 -> RemoteImpl.createChrome(encodedBytes, request, consumer)
  -> 生成userId
  -> 获取用户锁（30秒超时）
  -> 检查浏览器状态:
     a. 实例不存在 -> OPEN_ERROR
     b. 状态为PAGE_CONTROL_ERROR -> PAGE_CONTROL_ERROR
     c. 调用Moon SDK登录，比较配置 -> REOPEN 或 NORMAL
  -> 如果状态不是NORMAL:
     a. chromeSet.deleteForRestart(userId) - 删除实例（不断开连接）
     b. createInstance(request, encodedBytes) - 创建新实例
        - chromeSet.create(request) - 创建UserChrome
        - Moon SDK登录，获取配置
        - 计算扩展路径
        - 创建录制配置
        - userChrome.createBrowser(recordConfig) - 创建浏览器进程
  -> 如果consumer不为null（用户连接场景）:
     a. Moon SDK登录
     b. 通知控制连接已建立
     c. 执行回调
     d. 处理控制事件
     e. 清除告警
  -> 释放锁
```

### 7.2 容错处理流程

```
异常场景 -> RemoteImpl.fallback(sessionID) 或 fallbackByError(sessionId)
  -> 获取浏览器实例
  -> chrome.closeApp() - 关闭应用
     - 断开控制+媒体TCP连接
     - 保存用户数据到本地
     - 上传用户数据到S3
  -> 如果byError为true:
     - 设置状态为PAGE_CONTROL_ERROR
```

### 7.3 用户绑定更新流程

```
RemoteImpl.updateUserBind(sessionID)
  -> 创建UserBind对象
  -> 设置所有端点信息（从config获取）
  -> POST请求到CSE: /user-bind/v1/update
  -> 返回UserBind对象
```

### 7.4 数据统计上报流程

```
媒体/控制流量统计 -> RemoteImpl.sendTrafficMedia/Control(dataJson)
  -> POST请求到CSE: /stats/v1/traffic/media 或 /stats/v1/traffic/control
  -> 请求体为JSON字符串
  -> 异常时打印error日志
```

### 7.5 事件上报流程

```
RemoteImpl.reportEvent(event)
  -> ReportEventUtil.reportServerEvent(event, endpoint)
     - 构建URL: http://{endpoint}/server/event/v1/uploadEvent
     - 设置日期格式
     - 序列化为JSON
     - POST请求
     - 异常时打印error日志
```

## 8. 线程安全设计

### 8.1 并发控制

| 组件 | 线程安全机制 | 说明 |
|------|-------------|------|
| lockMap | ConcurrentHashMap | 线程安全的锁映射表 |
| ReentrantLock | JDK锁 | 用户级别的可重入锁 |
| createChrome() | tryLock + finally | 确保锁的获取和释放 |

### 8.2 锁超时机制

- **超时时间**: 30秒（LOCK_TIMEOUT_SECONDS）
- **超时处理**: 抛出RuntimeException("get lock timeout!")
- **锁释放**: finally块中确保释放，即使发生异常

### 8.3 锁清理机制

- 每次使用完锁后，调用`lockManager.removeLock(userId)`清理
- 避免锁对象长期占用内存

## 9. 异常处理

### 9.1 RemoteImpl层

#### 9.1.1 getUserBind()
- catch RuntimeException，打印error日志，返回null

#### 9.1.2 createChrome()
- 锁超时：抛出RuntimeException
- 其他异常：catch后删除实例，发送告警，打印error日志

#### 9.1.3 updateUserBind()
- catch RuntimeException，打印error日志，返回null

#### 9.1.4 sendTrafficMedia/Control/Session()
- catch RuntimeException，打印error日志（不抛异常）
- sendTrafficControl的错误日志内容为: "report media traffic data failed: {}."（注意：日志内容与实际方法名不一致）

#### 9.1.5 reportEvent()
- 由ReportEventUtil内部处理异常，打印error日志

### 9.2 LockManager层

- 无异常处理（使用JDK标准库，异常向上传播）
