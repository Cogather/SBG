# BrowserGateway 健康监控模块设计说明书

## 1. 概述

### 1.1 模块定位
健康监控模块是BrowserGateway系统运维层的核心模块，负责系统运行时的多维度健康状态检测。模块采用**策略模式**实现可扩展的检查机制，通过`HealthCheckTask`定时调度器统一编排CPU使用率检查、内存使用率检查、网络接口检查三种策略，并将检查结果通过告警服务和服务管理适配器进行告警通知与状态上报。

### 1.2 设计目标
- **多维度健康检查**：同时监控CPU使用率、内存使用率、网络接口状态
- **滞后阈值机制**：采用触发阈值/恢复阈值双阈值设计，防止状态频繁抖动
- **策略模式扩展**：通过`ICheckStrategy`接口实现检查策略的可插拔扩展
- **告警联动**：检测到不健康状态时自动发送告警（ALARM_300032），恢复时自动清除告警
- **状态上报**：将健康状态实时上报到服务管理适配器（CSE服务注册中心）
- **定时调度**：基于`ScheduledExecutorService`实现固定频率的周期性检查

健康监控模块采用**策略模式（Strategy Pattern）**：

```

│  └───────────────────┘  │

         ▼
┌─────────────────────────┐
│    <<interface>>         │
│    ICheckStrategy        │  ← 策略接口
│  + check(): HealthCheck  │
│           Result         │
└────────┬────────────────┘
         │
    ┌────┼──────────┐
    ▼    ▼          ▼
┌──────┐┌──────┐ ┌──────────────┐
│CpuUsa││Memory│ │NetWorkInterfa│
│geChec││Usage │ │ceCheck       │
│k     ││Check │ │              │
└──────┘└──────┘ └──────────────┘
  策略A    策略B      策略C
```

## 3. 详细设计

### 3.1 ICheckStrategy 接口定义

**包路径**: `com.huawei.browsergateway.service.healthCheck.ICheckStrategy`

```java
public interface ICheckStrategy {
    HealthCheckResult check();
}
```

**说明**: 健康检查策略的统一接口，所有检查策略均需实现此接口。`check()`方法执行具体的健康检查逻辑，返回`HealthCheckResult`对象。

### 3.2 HealthCheckResult 检查结果实体

**包路径**: `com.huawei.browsergateway.service.healthCheck.HealthCheckResult`

**注解**: `@Data`（Lombok生成getter/setter/toString等）

#### 3.2.1 字段定义

| 字段名 | 类型 | 说明 |
|--------|------|------|
| healthy | boolean | 是否健康（true=健康，false=不健康） |
| errorMsg | String | 错误信息（不健康时包含具体原因） |
| checkItem | String | 检查项名称（如"CpuUsageCheck"、"MemoryUsageCheck"、"NetWorkInterface"） |

### 3.3 HealthCheckTask 健康检查调度器

**包路径**: `com.huawei.browsergateway.scheduled.HealthCheckTask`

**Spring注解**: `@Component`

#### 3.3.1 字段定义

| 字段名 | 类型 | 注入方式 | 说明 |
|--------|------|---------|------|
| log | Logger | static final | Log4j2日志记录器 |
| strategies | `List<ICheckStrategy>` | @PostConstruct中初始化 | 健康检查策略列表 |
| isHealthy | boolean | 实例字段 | 当前健康状态 |
| checkErrMsg | String | 实例字段 | 检查错误信息 |
| cpuTriggerThreshold | float | @Value("${browsergw.healthCheck.cpu-trigger-threshold}") | CPU触发阈值 |
| cpuRecoverThreshold | float | @Value("${browsergw.healthCheck.cpu-recover-threshold}") | CPU恢复阈值 |
| memoryTriggerThreshold | float | @Value("${browsergw.healthCheck.memory-trigger-threshold}") | 内存触发阈值 |
| memoryRecoverThreshold | float | @Value("${browsergw.healthCheck.memory-recover-threshold}") | 内存恢复阈值 |
| alarm | IAlarm | @Autowired | 告警管理服务 |
| serviceManagementAdapter | ServiceManagementAdapter | @Autowired | 服务管理适配器 |
| period | long | @Value("${browsergw.scheduled.health-check-period:60000}") | 检查周期（毫秒），默认60000 |
| scheduler | ScheduledExecutorService | @PostConstruct中初始化 | 定时任务调度器 |

#### 3.3.2 init() 初始化方法

**修饰符**: `private`

**注解**: `@PostConstruct`

**功能**: Bean初始化后自动调用，初始化健康检查策略列表并启动定时调度器

**执行流程**:
```
1. 打印info日志，记录四个阈值参数:
   "cpuTriggerThreshold:{}, cpuRecoverThreshold:{}, memoryTriggerThreshold:{}, memoryRecoverThreshold:{}"
2. 初始化策略列表 strategies = new ArrayList<>()
3. 添加CPU使用率检查策略:
   strategies.add(new CpuUsageCheck(cpuTriggerThreshold, cpuRecoverThreshold))
4. 添加内存使用率检查策略:
   strategies.add(new MemoryUsageCheck(memoryTriggerThreshold, memoryRecoverThreshold))
5. 添加网络接口检查策略:
   strategies.add(new NetWorkInterfaceCheck())
6. 创建单线程定时调度器:
   scheduler = Executors.newSingleThreadScheduledExecutor()
7. 启动固定频率定时任务:
   scheduler.scheduleAtFixedRate(this::checkAndReport, 0, period, TimeUnit.MILLISECONDS)
   - initialDelay = 0（立即执行第一次）
   - period = 配置的检查周期
8. 打印info日志 "Health check task initialized, period: {}ms"
```

#### 3.3.3 checkAndReport() 方法

**修饰符**: `private`

**功能**: 执行健康检查并上报结果，作为定时任务的执行入口

**执行流程**:
```
1. 调用 check() - 执行所有健康检查策略
2. 调用 report() - 上报检查结果并处理告警
```

#### 3.3.4 check() 方法

**修饰符**: `private`

**功能**: 遍历所有健康检查策略，汇总检查结果

**执行流程**:
```
1. 初始化局部变量 isHealthy = true
2. 初始化 errMsg = new StringBuilder()
3. 遍历 strategies 列表中的每个策略:
   a. 调用 strategy.check() 获取 HealthCheckResult
   b. 如果 check.isHealthy() == false:
      - 设置 isHealthy = false
      - 将 check.getErrorMsg() 追加到 errMsg
4. 将汇总结果赋值到实例字段:
   this.isHealthy = isHealthy
   this.checkErrMsg = errMsg.toString()
```

**说明**: 任何一个策略检查不通过，整体状态即为不健康。所有策略的错误信息会拼接在一起。

#### 3.3.5 report() 方法

**修饰符**: `private`

**功能**: 上报健康检查结果到服务管理适配器，并根据健康状态发送/清除告警

**执行流程**:
```
1. 创建 healthResult = new HashMap<String, String>()
2. 设置属性:
   healthResult.put("isHealthy", Boolean.toString(isHealthy))
   healthResult.put("checkMsg", checkErrMsg)
3. 处理告警:
   - 如果 isHealthy == true:
     调用 alarm.clearAlarm(AlarmEnum.ALARM_300032.getAlarmId())
     → 清除告警ID "300032"
   - 如果 isHealthy == false:
     调用 alarm.sendAlarm(new AlarmEvent(AlarmEnum.ALARM_300032, "Sub‑health check failed"))
     → 发送告警，告警枚举为ALARM_300032，消息为"Sub‑health check failed"
4. 上报健康状态到服务管理适配器:
   - 如果 serviceManagementAdapter != null:
     调用 serviceManagementAdapter.reportInstanceProperties(healthResult)
```

**上报属性Map结构**:

| Key | Value类型 | 说明 |
|-----|----------|------|
| isHealthy | String | "true"或"false"，当前健康状态 |
| checkMsg | String | 错误信息拼接字符串，健康时为空字符串 |

#### 3.3.6 destroy() 方法

**修饰符**: `public`

**注解**: `@PreDestroy`

**功能**: Bean销毁前关闭定时调度器，释放线程资源

**执行流程**:
```
1. 如果 scheduler != null:
   a. 调用 scheduler.shutdown()
   b. 打印info日志 "Health check task destroyed."
```

### 3.4 CpuUsageCheck CPU使用率检查策略

**包路径**: `com.huawei.browsergateway.service.healthCheck.CpuUsageCheck`

**实现接口**: `ICheckStrategy`

#### 3.4.1 字段定义

| 字段名 | 类型 | 修饰符 | 说明 |
|--------|------|--------|------|
| log | Logger | private static final | SLF4J日志记录器 |
| inHighUsage | boolean | private | 当前是否处于高负载状态（用于滞后阈值判断） |
| triggerThreshold | float | private final | 触发阈值（超过此值判定为不健康） |
| recoverThreshold | float | private final | 恢复阈值（降至此值以下才恢复健康） |
| resourceMonitorAdapter | ResourceMonitorAdapter | @Autowired | 资源监控适配器 |

#### 3.4.2 构造函数

```java
public CpuUsageCheck(float triggerThreshold, float recoverThreshold)
```

**执行流程**:
```
1. 设置 this.triggerThreshold = triggerThreshold
2. 设置 this.recoverThreshold = recoverThreshold
3. 打印info日志 "start to check cpu usage, triggerThreshold: {}, recoverThreshold:{}"
```

#### 3.4.3 check() 方法

**功能**: 检查CPU使用率是否超过阈值

**返回值**: `HealthCheckResult`

**执行流程**:
```
1. 创建 result = new HealthCheckResult()
2. 设置 result.setCheckItem("CpuUsageCheck")
3. 设置 result.setHealthy(true)（默认健康）
4. 如果 resourceMonitorAdapter == null:
   - 打印warn日志 "ResourceMonitorAdapter is not available"
   - 直接返回result（默认健康）
5. 调用 resourceMonitorAdapter.getStatistics("cpu") 获取CPU统计信息
6. 如果 cpuStatistics.isSuccess() == false:
   - 直接返回result（获取失败时默认健康）
7. 滞后阈值判断:
   - 如果 inHighUsage == true（已处于高负载状态）:
     result.setHealthy(cpuStatistics.getRatio() < recoverThreshold)
     → 需要降至恢复阈值以下才认为健康
   - 如果 inHighUsage == false（正常状态）:
     result.setHealthy(cpuStatistics.getRatio() < triggerThreshold)
     → 超过触发阈值才认为不健康
8. 更新高负载状态: inHighUsage = !result.isHealthy()
9. 如果 inHighUsage == true:
   result.setErrorMsg(String.format("cpu in high usage[%f];", cpuStatistics.getRatio()))
10. 返回result
```

**滞后阈值机制说明**:

```
                    触发阈值(90%)         恢复阈值(80%)
CPU使用率   ────────────┬─────────────────┬──────────────
                        │                 │
正常→不健康:     usage >= 90%时触发        │
不健康→正常:            │         usage < 80%时恢复
                        │                 │
                        │   [滞后区间]     │
                        │   80%~90%之间    │
                        │   保持当前状态    │
```

此设计避免了CPU使用率在阈值附近波动时频繁切换健康/不健康状态。

3. 遍历 interfaceList 中的每个接口名称 name:
   a. try:
      - 调用 NetworkInterface.getByName(name) 获取网络接口对象 ni
      - 如果 ni == null（接口不存在）:
        isHealthy = false
        errMsg.append(String.format("interface %s not found;", name))
      - 否则如果 !ni.isUp()（接口已关闭）:
        isHealthy = false
        errMsg.append(String.format("interface %s is down;", name))
   b. catch (SocketException e):
      - 打印error日志 "get interface error"
4. 如果 !isHealthy:
   - 打印warn日志 "[NetWorkInterfaceCheck] check result: {errMsg}"
5. 创建 result = new HealthCheckResult()
6. 设置 result.setHealthy(isHealthy)
7. 设置 result.setErrorMsg(errMsg.toString())
8. 设置 result.setCheckItem("NetWorkInterface")
9. 返回result
```

**检查的网络接口**:

| 接口名称 | 用途 |
|---------|------|
| bond-base | 基础网络平面 |
| bond-external | 外部网络平面 |

**异常处理**: `SocketException`异常仅记录日志，不影响其他接口的检查。

**适配器实现**:

| 实现类 | 环境 | 实现方式 |
|--------|------|---------|
| CspResourceMonitorAdapter | 内网（CSP SDK） | 通过反射调用`RsApi.getLatestContainerResourceStatistics(metricType)` |

#### 5.3.1 CspResourceMonitorAdapter 实现细节

**包路径**: `com.huawei.browsergateway.adapter.impl.csp.CspResourceMonitorAdapter`

**注解**: `@Component("cspResourceMonitorAdapter")`

**getStatistics(String metricType) 执行流程**:
```
1. 通过反射加载 com.huawei.csp.csejsdk.resdk.api.RsApi 类
2. 获取 getLatestContainerResourceStatistics(String) 方法
3. 调用该方法获取资源统计结果
4. 如果结果为null:
   - 返回空统计信息（success=false, ratio=0.0）
5. 通过反射获取结果的 isSuccess() 和 getRatio() 方法
6. 构建 ResourceStatistics 对象并返回
7. 异常时打印error日志，返回空统计信息
```

#### 5.3.2 CustomResourceMonitorAdapter 实现细节

**包路径**: `com.huawei.browsergateway.adapter.impl.custom.CustomResourceMonitorAdapter`

**注解**: `@Component("customResourceMonitorAdapter")`

**getStatistics(String metricType) 执行流程**:
```
1. 创建 stats = new ResourceStatistics()
2. 设置 stats.setTimestamp(System.currentTimeMillis())
3. 根据 metricType 分支处理:
   a. "cpu":
      - 获取 OperatingSystemMXBean
      - 如果是 com.sun.management.OperatingSystemMXBean:
        使用 getProcessCpuLoad() * 100 作为CPU使用率
      - 否则:
        使用 getSystemLoadAverage() * 10 作为近似值
   b. "memory":
      - 获取 MemoryMXBean
      - 计算 heapUsage.getUsed() * 100.0 / heapUsage.getMax() 作为内存使用率
      - 设置 available = max - used, capacity = max
   c. 其他:
      - success=false, ratio=0.0
4. 异常时打印error日志，返回success=false的统计信息
```

### 7.1 健康检查完整流程

```

    [CpuUsageCheck(90, 80), MemoryUsageCheck(90, 80), NetWorkInterfaceCheck()]

  → 每60秒执行一次 checkAndReport()

checkAndReport() 执行流程:

## 8. 线程安全设计

### 8.1 并发控制

| 组件 | 线程安全机制 | 说明 |
|------|-------------|------|
| HealthCheckTask.scheduler | SingleThreadScheduledExecutor | 单线程调度，check()和report()串行执行，无并发问题 |
| CpuUsageCheck.inHighUsage | 单线程访问 | 由HealthCheckTask单线程调度器保证串行访问 |
| MemoryUsageCheck.inHighUsage | 单线程访问 | 由HealthCheckTask单线程调度器保证串行访问 |
| isHealthy / checkErrMsg | 实例字段 | 由单线程写入，report()读取时在同一线程内 |

### 8.2 资源管理

- `ScheduledExecutorService`在`@PreDestroy`时调用`shutdown()`确保线程池正确关闭
- 策略对象在`@PostConstruct`中通过`new`创建，生命周期与HealthCheckTask Bean一致

## 9. 异常处理

### 9.1 策略级异常处理

| 策略 | 异常场景 | 处理方式 |
|------|---------|---------|
| CpuUsageCheck | ResourceMonitorAdapter为null | 打印warn日志，返回默认健康结果 |
| CpuUsageCheck | getStatistics()返回success=false | 返回默认健康结果（不影响整体判断） |
| MemoryUsageCheck | ResourceMonitorAdapter为null | 打印warn日志，返回默认健康结果 |
| MemoryUsageCheck | getStatistics()返回success=false | 返回默认健康结果 |
| NetWorkInterfaceCheck | SocketException | 打印error日志，继续检查下一个接口 |

### 9.2 调度器级异常处理

- `checkAndReport()`方法内部的异常不会导致定时任务停止（`ScheduledExecutorService`的`scheduleAtFixedRate`会捕获异常）
- 各策略的`check()`方法内部已做异常处理，不会向上抛出未检查异常

### 9.3 降级策略

- **资源监控适配器不可用时**: CPU和内存检查默认返回健康状态（宁可漏报不误报）
- **网络接口检查异常时**: 单个接口的`SocketException`不影响其他接口的检查
- **服务管理适配器为null时**: 跳过状态上报（`if (serviceManagementAdapter != null)`保护）

## 11. 扩展指南

### 11.1 新增检查策略

要添加新的健康检查策略（如磁盘空间检查），只需：

1. **实现ICheckStrategy接口**:

```java
package com.huawei.browsergateway.service.healthCheck;

public class DiskSpaceCheck implements ICheckStrategy {
    @Override
    public HealthCheckResult check() {
        HealthCheckResult result = new HealthCheckResult();
        result.setCheckItem("DiskSpaceCheck");
        // 实现磁盘空间检查逻辑
        result.setHealthy(true);
        return result;
    }
}
```

2. **在HealthCheckTask.init()中注册**:

```java
strategies.add(new DiskSpaceCheck());
```

### 11.2 注意事项

- CpuUsageCheck和MemoryUsageCheck通过`new`创建而非Spring Bean注入，因此其`@Autowired ResourceMonitorAdapter`字段**不会被Spring自动注入**。实际运行时`resourceMonitorAdapter`为null，检查逻辑会走到null保护分支返回默认健康结果。若需要ResourceMonitorAdapter生效，需要将策略类改为Spring Bean或手动注入依赖。
- NetWorkInterfaceCheck中的接口列表（`bond-base`、`bond-external`）是硬编码的，后续可考虑配置化。
