# BrowserGateway 告警管理模块设计说明书

## 1. 概述

### 1.1 模块定位
告警管理模块是BrowserGateway系统的运维层模块，负责系统运行过程中异常事件的告警发送、告警清除和历史告警处理。模块通过`IAlarm`接口对外提供服务，由`AlarmServiceImpl`实现，通过`AlarmAdapter`适配器接口对接不同的告警底层实现（CSP SDK环境或自定义外网环境）。

### 1.2 设计目标
- **告警发送**：当系统出现异常时（如插件创建失败、浏览器创建失败、健康检查不通过等），向告警平台发送告警
- **告警去重**：同一告警在10分钟内不重复发送，避免告警风暴
- **告警清除**：当异常恢复后，自动清除对应告警
- **历史告警处理**：系统启动时自动查询并清除历史遗留告警
- **多环境适配**：通过适配器模式支持CSP SDK内网环境和自定义外网环境

### 2.4 数据存储

告警管理模块使用内存级`ConcurrentHashMap`存储告警去重记录：

```java
public static ConcurrentHashMap<String, Long> alarmMap = new ConcurrentHashMap<>();
```

- **Key**: alarmId（告警ID，如"300030"、"300031"等）
- **Value**: 上次告警发送时间的毫秒时间戳（`System.currentTimeMillis()`）


### 3.2 AlarmServiceImpl 实现

**包路径**: `com.huawei.browsergateway.service.impl.AlarmServiceImpl`

**Spring注解**: `@Service`

#### 3.2.1 字段定义

| 字段名 | 类型 | 修饰符 | 注入方式 | 说明 |
|--------|------|--------|---------|------|
| log | `Logger` | private static final | - | Log4j2日志记录器 |
| ONE_MINUTE | `Integer` | private static final = 10 * 60 * 1000 | - | 告警去重间隔（10分钟，600000毫秒） |
| alarmMap | `ConcurrentHashMap<String, Long>` | public static | - | 告警去重记录表（alarmId → 上次发送时间戳） |
| alarmAdapter | `AlarmAdapter` | private | @Autowired | 告警适配器（由AdapterBeanConfiguration自动选择实现） |
| systemUtilAdapter | `SystemUtilAdapter` | private | @Autowired | 系统工具适配器 |
| isInitialized | `boolean` | private | - | 初始化标志，防止重复执行启动逻辑 |

#### 3.2.2 sendAlarm(AlarmEvent alarmEvent) 方法

**功能**: 发送告警，带10分钟去重机制

**执行流程**:
```
1. 打印info日志"enter send alarm"
2. 去重检查：
   - 从alarmMap获取该告警ID的上次发送时间（默认0L）
   - 如果 当前时间 - 上次发送时间 < ONE_MINUTE（600000ms）
     - 打印info日志"An alarm was already reported within 10 minute; skipping this operation."
     - 返回false
3. 构建告警参数Map：
   - "EventMessage" → alarmEvent.getEventMessage()
   - "EventSource" → "BrowserGW Service"
   - "OriginalEventTime" → TimeUtil.getCurrentDate()（GMT时区，格式yyyy-MM-dd HH:mm:ss）
4. 调用alarmAdapter.sendAlarm(alarmId, AlarmAdapter.AlarmType.GENERATE, parameters)
5. 如果发送成功（result == true）：
   - 将alarmId和当前时间戳存入alarmMap
   - 打印info日志"send alarm successfully."
6. 如果发送失败：
   - 打印info日志"Failed to send alarm."
7. 返回result
```

#### 3.2.3 clearAlarm(String alarmId) 方法

**功能**: 清除指定告警

**执行流程**:
```
1. 检查alarmMap是否包含该alarmId
   - 不包含：直接返回false（该告警未被发送过，无需清除）
2. 调用alarmAdapter.clearAlarm(alarmId)
3. 如果清除成功（result == true）：
   - 从alarmMap中移除该alarmId
   - 打印info日志"send recover alarm successfully."
4. 如果清除失败：
   - 打印info日志"Failed to send recover alarm."
5. 返回result
```

#### 3.2.4 runAfterStartup(ContextRefreshedEvent event) 方法

**功能**: Spring容器启动完成后自动执行，处理历史遗留告警

**注解**: `@EventListener(ContextRefreshedEvent.class)`

**执行流程**:
```
1. 检查isInitialized标志
   - 如果已初始化：打印info日志"Initialization attempt skipped as it was already completed."，直接返回
2. 打印info日志"start runAfterStartup."
3. 调用handleHistoryAlarm()处理历史告警
4. 打印info日志"end runAfterStartup."
5. 设置isInitialized = true
```

#### 3.2.5 handleHistoryAlarm() 方法

**功能**: 查询并清除所有历史活跃告警

**执行流程**:
```
1. 调用AlarmEnum.getAllCodes()获取所有告警ID拼接字符串（用"&"分隔）
   - 例如："300030&300031&300032&300033"
2. 将拼接字符串按"&"分割为List<String>
3. 调用alarmAdapter.queryHistoricalAlarms(alarmIds)查询历史活跃告警
4. 如果返回null或空列表：
   - 打印info日志"get alarm fail or no active alarms, skip it"
   - 直接返回
5. 遍历每条历史告警AlarmInfo：
   a. 打印info日志，输出告警信息JSON
   b. 构建告警参数Map：
      - "EventMessage" → alarmInfo.getMessage()
      - "EventSource" → "BrowserGW Service"
      - "OriginalEventTime" → String.valueOf(alarmInfo.getTimestamp())
   c. 调用alarmAdapter.clearAlarm(alarmInfo.getAlarmId())清除告警
   d. 打印清除结果日志
6. 异常处理：catch所有异常，打印info日志"ignore all exception"
```

### 3.3 AlarmAdapter 适配器接口

**包路径**: `com.huawei.browsergateway.adapter.AlarmAdapter`

```java
public interface AlarmAdapter {
    // 发送告警
    boolean sendAlarm(String alarmId, AlarmType type, Map<String, String> parameters);

    // 清除告警
    boolean clearAlarm(String alarmId);

    // 批量发送告警（支持重试）
    int sendAlarmsBatch(List<AlarmRequest> alarms, int maxRetry);

    // 查询历史告警
    List<AlarmInfo> queryHistoricalAlarms(List<String> alarmIds);

    // 告警类型枚举
    enum AlarmType {
        GENERATE,   // 产生告警
        CLEAR       // 清除告警
    }
}
```

#### 3.4.2 sendAlarm(String alarmId, AlarmType type, Map<String, String> parameters) 方法

**功能**: 通过CSP SDK反射调用发送告警

**执行流程**:
```
1. 去重检查：
   - 如果 当前时间 - lastAlarmTime.getOrDefault(alarmId, 0L) < ALARM_DEDUPE_INTERVAL
   - 打印warn日志，返回false
2. 通过反射加载CSP SDK类：
   a. 加载AlarmModel类：Class.forName("com.huawei.csp.om.alarmsdk.alarmmodel.AlarmModel")
   b. 获取告警类型枚举值：getAlarmTypeEnum(alarmModelClass, type)
      - 加载枚举类：Class.forName("com.huawei.csp.om.alarmsdk.alarmmodel.AlarmModel$EuGenClearType")
      - 根据type映射：GENERATE → "GENERATE"，CLEAR → "CLEAR"
   c. 加载Alarm类：Class.forName("com.huawei.csp.om.alarmsdk.alarmmanager.Alarm")
   d. 创建Alarm实例：new Alarm(alarmId, alarmType)
3. 设置默认参数（通过反射调用appendParameter方法）：
   - "source" → systemUtilAdapter.getEnvString("SERVICENAME", "browser-gateway")
   - "kind" → "service"
   - "name" → systemUtilAdapter.getEnvString("PODNAME", "unknown")
   - "namespace" → systemUtilAdapter.getEnvString("NAMESPACE", "default")
   - "EventSource" → "BrowserGateway Service"
   - "OriginalEventTime" → String.valueOf(System.currentTimeMillis())
4. 设置自定义参数：遍历parameters Map，逐个调用appendParameter
5. 通过反射发送告警：
   a. 加载AlarmSendManager类：Class.forName("com.huawei.csp.om.alarmsdk.alarmmanager.AlarmSendManager")
   b. 获取单例：AlarmSendManager.getInstance()
   c. 调用sendAlarm(alarm)
6. 如果发送成功：更新lastAlarmTime
7. 返回发送结果
```

**异常处理**: catch所有异常，打印error日志，返回false

#### 3.4.3 clearAlarm(String alarmId) 方法

**功能**: 通过CSP SDK反射调用清除告警

**执行流程**:
```
1. 检查lastAlarmTime是否包含alarmId
   - 不包含：返回false
2. 通过反射创建CLEAR类型的Alarm对象
3. 通过AlarmSendManager.getInstance().sendAlarm(alarm)发送清除告警
4. 如果成功：从lastAlarmTime移除该alarmId
5. 返回结果
```

**异常处理**: catch所有异常，打印error日志，返回false

#### 3.4.4 sendAlarmsBatch(List<AlarmRequest> alarms, int maxRetry) 方法

**功能**: 批量发送告警，支持重试

**执行流程**:
```
1. 初始化successCount = 0
2. 遍历每个AlarmRequest：
   a. 调用sendAlarmWithRetry(alarm, maxRetry)
   b. 成功则successCount++
3. 返回successCount
```

**sendAlarmWithRetry私有方法**:
```
1. 确定最大重试次数：alarm.getMaxRetry() != null ? alarm.getMaxRetry() : maxRetry
2. 初始化retryCount = 0，retryDelay = 5000L（5秒）
3. while (retryCount < maxRetryCount):
   a. 调用sendAlarm(alarm.getAlarmId(), alarm.getType(), alarm.getParameters())
   b. 成功则返回true
   c. 失败则打印error日志
   d. retryCount++
   e. 如果还有重试机会：Thread.sleep(retryDelay)
   f. 如果被中断：Thread.currentThread().interrupt()，退出循环
4. 返回false
```

#### 3.4.5 queryHistoricalAlarms(List<String> alarmIds) 方法

**功能**: 通过CSP FMService查询历史活跃告警

**执行流程**:
```
1. 获取appId：systemUtilAdapter.getEnvString("appId", "0")
2. 构建JSON请求参数：
   {
     "cmd": "GET_ACTIVE_ALARMS",
     "language": "en-us",
     "data": {
       "appId": "{appId}",
       "alarmIds": "{alarmIds逗号分隔}"
     }
   }
3. 通过反射创建CspRestTemplate：
   Class.forName("com.huawei.csp.jsf.api.CspRestTemplateBuilder").create()
4. 发送POST请求到GET_ALARM_INTERFACE
5. 如果响应状态码为200：解析响应并返回AlarmInfo列表
6. 否则返回空列表
```

**异常处理**: catch所有异常，打印error日志，返回空列表

#### 3.5.2 sendAlarm(String alarmId, AlarmType type, Map<String, String> parameters) 方法

**功能**: 将告警写入本地日志文件

**执行流程**:
```
1. 去重检查：
   - 如果 当前时间 - lastAlarmTime.getOrDefault(alarmId, 0L) < ALARM_DEDUPE_INTERVAL
   - 打印warn日志，返回false
2. 格式化告警日志：formatAlarmLog(alarmId, type, parameters)
   - 格式："[yyyy-MM-dd HH:mm:ss] ALARM_ID={alarmId} TYPE={type} {key}={value} ..."
3. 写入告警日志文件：writeAlarmLog(alarmLog)
   - 使用FileWriter追加模式写入logFilePath
4. 同时记录到应用日志（warn级别）
5. 更新lastAlarmTime
6. alarmCounter自增
7. 返回true
```

**异常处理**: catch所有异常，打印error日志，返回false

#### 3.5.3 clearAlarm(String alarmId) 方法

**功能**: 清除告警记录并写入日志

**执行流程**:
```
1. 检查lastAlarmTime是否包含alarmId
   - 不包含：返回false
2. 格式化清除日志：formatClearLog(alarmId)
   - 格式："[yyyy-MM-dd HH:mm:ss] ALARM_CLEARED: ALARM_ID={alarmId}"
3. 写入告警日志文件
4. 打印info日志"Alarm cleared: {alarmId}"
5. 从lastAlarmTime移除该alarmId
6. 返回true
```

**异常处理**: catch所有异常，打印error日志，返回false

#### 3.5.4 sendAlarmsBatch(List<AlarmRequest> alarms, int maxRetry) 方法

**功能**: 批量发送告警（逐个发送，不支持重试）

**执行流程**:
```
1. 初始化successCount = 0
2. 遍历每个AlarmRequest，调用sendAlarm
3. 成功则successCount++
4. 返回successCount
```

#### 3.5.5 queryHistoricalAlarms(List<String> alarmIds) 方法

**功能**: 查询历史告警（外网环境不支持）

**返回值**: 空ArrayList

### 3.6 适配器Bean自动选择

**包路径**: `com.huawei.browsergateway.config.AdapterBeanConfiguration`

**注解**: `@Configuration`

告警适配器的Bean通过`AdapterBeanConfiguration`自动选择：

```java
@Bean
@Primary
public AlarmAdapter alarmAdapter(
        @Autowired(required = false) CspAlarmAdapter cspAdapter,
        @Autowired(required = false) CustomAlarmAdapter customAdapter) {
    if (cspAdapter != null) {
        return cspAdapter;  // 优先使用CSP SDK实现
    } else if (customAdapter != null) {
        return customAdapter;  // 其次使用自定义实现
    } else {
        throw new IllegalStateException("No AlarmAdapter implementation found");
    }
}
```

**选择逻辑**:
1. 优先选择`CspAlarmAdapter`（CSP SDK环境）
2. 其次选择`CustomAlarmAdapter`（外网自定义环境）
3. 两者都不可用时抛出`IllegalStateException`

## 7. 关键流程

### 7.1 告警发送完整流程

```
调用方（HealthCheckTask/RemoteImpl/PluginManageImpl）
  -> new AlarmEvent(AlarmEnum.ALARM_XXXXX, "告警消息")
  -> IAlarm.sendAlarm(alarmEvent)
    -> AlarmServiceImpl.sendAlarm(alarmEvent)
      -> 去重检查（alarmMap中检查10分钟内是否已发送）
      -> 构建参数Map（EventMessage、EventSource、OriginalEventTime）
      -> AlarmAdapter.sendAlarm(alarmId, GENERATE, parameters)
        -> [CSP环境] CspAlarmAdapter:
          -> 适配器层去重检查
          -> 反射加载CSP SDK AlarmModel
          -> 创建Alarm对象（alarmId, GENERATE类型）
          -> 设置默认参数（source、kind、name、namespace等）
          -> 设置自定义参数
          -> AlarmSendManager.getInstance().sendAlarm(alarm)
        -> [外网环境] CustomAlarmAdapter:
          -> 适配器层去重检查
          -> 格式化告警日志
          -> 写入本地告警日志文件
          -> 记录到应用日志
      -> 更新alarmMap去重记录
```

### 7.2 告警清除完整流程

```
调用方（HealthCheckTask/RemoteImpl/PluginManageImpl）
  -> IAlarm.clearAlarm(alarmId)
    -> AlarmServiceImpl.clearAlarm(alarmId)
      -> 检查alarmMap是否包含该alarmId（未发送过则直接返回false）
      -> AlarmAdapter.clearAlarm(alarmId)
        -> [CSP环境] CspAlarmAdapter:
          -> 检查lastAlarmTime
          -> 反射创建CLEAR类型Alarm对象
          -> AlarmSendManager.getInstance().sendAlarm(alarm)
          -> 成功后移除lastAlarmTime记录
        -> [外网环境] CustomAlarmAdapter:
          -> 检查lastAlarmTime
          -> 格式化清除日志
          -> 写入本地告警日志文件
          -> 移除lastAlarmTime记录
      -> 成功后从alarmMap移除该alarmId
```

### 7.3 系统启动历史告警处理流程

```
Spring容器启动完成
  -> ContextRefreshedEvent事件触发
  -> AlarmServiceImpl.runAfterStartup(event)
    -> 检查isInitialized标志（防止重复执行）
    -> handleHistoryAlarm()
      -> AlarmEnum.getAllCodes() → "300030&300031&300032&300033"
      -> 分割为List<String>
      -> AlarmAdapter.queryHistoricalAlarms(alarmIds)
        -> [CSP环境] CspAlarmAdapter:
          -> 构建JSON请求
          -> 通过CspRestTemplate POST到FMService
          -> 解析响应
        -> [外网环境] CustomAlarmAdapter:
          -> 返回空列表（不支持历史查询）
      -> 遍历历史告警
        -> 逐个调用AlarmAdapter.clearAlarm(alarmId)清除
    -> 设置isInitialized = true
```

### 7.4 告警触发场景汇总

| 告警枚举 | 告警ID | 触发位置 | 触发条件 | 清除条件 |
|---------|--------|---------|---------|---------|
| ALARM_300030 | 300030 | PluginManageImpl.updateStatus() | pluginStatus不为"complete" | pluginStatus为"complete" |
| ALARM_300031 | 300031 | RemoteImpl.createChrome() | 异常消息包含"failed to create user interface" | createChrome成功完成 |
| ALARM_300032 | 300032 | HealthCheckTask.report() | 健康检查isHealthy为false | 健康检查isHealthy为true |
| ALARM_300033 | 300033 | RemoteImpl.createChrome() | 异常消息包含"failed to create browsers" | createChrome成功完成 |

## 8. 线程安全设计

### 8.1 并发控制

| 组件 | 线程安全机制 | 说明 |
|------|-------------|------|
| AlarmServiceImpl.alarmMap | ConcurrentHashMap | 告警去重记录表，线程安全 |
| CspAlarmAdapter.lastAlarmTime | ConcurrentHashMap | 适配器层去重记录，线程安全 |
| CustomAlarmAdapter.lastAlarmTime | ConcurrentHashMap | 适配器层去重记录，线程安全 |
| CustomAlarmAdapter.alarmCounter | AtomicInteger | 原子计数器，线程安全 |
| AlarmServiceImpl.isInitialized | boolean | 仅在启动时单线程写入，无并发问题 |

### 8.2 双层去重机制

告警模块实现了双层去重：
1. **服务层去重**（AlarmServiceImpl.alarmMap）：在业务逻辑层进行10分钟去重
2. **适配器层去重**（CspAlarmAdapter/CustomAlarmAdapter.lastAlarmTime）：在底层适配器层进行10分钟去重

两层去重确保即使在高并发场景下也不会产生告警风暴。

## 9. 异常处理

### 9.1 AlarmServiceImpl层

- sendAlarm()：去重检查失败返回false，发送失败返回false（不抛异常）
- clearAlarm()：告警未发送过返回false，清除失败返回false（不抛异常）
- handleHistoryAlarm()：catch所有异常，打印info日志"ignore all exception"（安全降级，不影响系统启动）

### 9.2 CspAlarmAdapter层

- sendAlarm()：反射调用失败时catch Exception，打印error日志，返回false
- clearAlarm()：反射调用失败时catch Exception，打印error日志，返回false
- queryHistoricalAlarms()：HTTP调用失败时catch Exception，打印error日志，返回空列表
- sendAlarmWithRetry()：每次重试失败打印error日志，线程中断时恢复中断标志

### 9.3 CustomAlarmAdapter层

- sendAlarm()：文件写入失败时catch Exception，打印error日志，返回false
- clearAlarm()：文件写入失败时catch Exception，打印error日志，返回false
- queryHistoricalAlarms()：直接返回空列表（不支持历史查询）

## 11. CSP SDK反射调用说明

由于告警管理模块需要兼容CSP SDK内网环境和外网自定义环境，`CspAlarmAdapter`通过Java反射机制调用CSP SDK API，避免编译时硬依赖CSP SDK包。

### 11.1 涉及的CSP SDK类

| 类全限定名 | 用途 |
|-----------|------|
| com.huawei.csp.om.alarmsdk.alarmmodel.AlarmModel | 告警模型类 |
| com.huawei.csp.om.alarmsdk.alarmmodel.AlarmModel$EuGenClearType | 告警类型枚举（GENERATE/CLEAR） |
| com.huawei.csp.om.alarmsdk.alarmmanager.Alarm | 告警对象 |
| com.huawei.csp.om.alarmsdk.alarmmanager.AlarmSendManager | 告警发送管理器（单例） |
| com.huawei.csp.jsf.api.CspRestTemplateBuilder | CSP RestTemplate构建器 |

### 11.2 反射调用链

**发送告警**:
```
AlarmModel.EuGenClearType.GENERATE → new Alarm(alarmId, type)
→ alarm.appendParameter(key, value) × N
→ AlarmSendManager.getInstance().sendAlarm(alarm)
```

**查询历史告警**:
```
CspRestTemplateBuilder.create() → RestTemplate
→ restTemplate.exchange(GET_ALARM_INTERFACE, POST, requestEntity, String.class)
```
