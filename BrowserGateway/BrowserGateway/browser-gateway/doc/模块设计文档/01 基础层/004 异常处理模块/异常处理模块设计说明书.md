# BrowserGateway 异常处理模块设计说明书

## 目录结构

本异常处理模块设计说明书涵盖异常处理相关的所有类，共3个文件：

- `exception/GlobalExceptionHandle.java` - 全局异常处理器
- `entity/CommonResult.java` - 统一响应结果封装（异常处理依赖）
- `entity/ResultCode.java` - 结果码枚举（异常处理依赖）

---

## 1. 模块概述

### 1.1 模块定位

异常处理模块是BrowserGateway系统的基础支撑模块，负责全局异常捕获、异常信息封装和错误日志记录。模块通过Spring的`@ControllerAdvice`机制实现全局异常处理，确保所有Controller层抛出的异常都能被统一捕获和处理。

### 1.2 模块职责

- **全局异常捕获**：捕获所有Controller层抛出的异常
- **异常信息封装**：将异常信息封装为统一的响应格式
- **错误日志记录**：记录异常详细信息，便于问题排查
- **统一响应格式**：确保所有异常响应都遵循统一的格式规范

### 1.3 架构设计

```
异常处理模块架构：
├── GlobalExceptionHandle（全局异常处理器）
│   ├── 使用 → CommonResult（统一响应封装）
│   └── 使用 → ResultCode（结果码枚举）
│
├── CommonResult（统一响应结果）
│   └── 使用 → ResultCode（结果码枚举）
│
└── ResultCode（结果码枚举）
    └── 定义系统所有错误码
```

### 1.4 依赖关系

**外部依赖**：
- `org.springframework.web.bind.annotation` - Spring Web注解（@ControllerAdvice、@ExceptionHandler）
- `org.apache.logging.log4j` - Log4j日志框架
- `javax.servlet.http` - Servlet API（HttpServletRequest）

**内部依赖**：
- `com.huawei.browsergateway.entity.CommonResult` - 统一响应结果封装
- `com.huawei.browsergateway.entity.ResultCode` - 结果码枚举

## 2. 核心类设计

### 2.1 GlobalExceptionHandle

**文件路径**: `exception/GlobalExceptionHandle.java`

**作用**: 全局异常处理器，使用Spring的`@ControllerAdvice`机制捕获所有Controller层抛出的异常，并统一封装为`CommonResult`响应格式。

**类设计**:
- **类型**: 异常处理器类
- **包路径**: `com.huawei.browsergateway.exception`
- **注解**: `@ControllerAdvice` - Spring全局异常处理注解
- **线程安全**: 是（无共享状态，方法级别处理）

**核心字段**:

| 字段名 | 类型 | 访问修饰符 | 说明 |
|--------|------|-----------|------|
| `log` | `Logger` | `private static final` | Log4j日志记录器 |

**字段初始化**:

```java
private static final Logger log = LogManager.getLogger(GlobalExceptionHandle.class);
```

**方法定义**:

#### 2.1.1 handleException(HttpServletRequest request, Exception ex)

**功能**: 处理所有类型的异常。

**注解**: `@ExceptionHandler(value = {Exception.class})`

**参数**:
- `request` (HttpServletRequest): HTTP请求对象（当前未使用，但保留在方法签名中）
- `ex` (Exception): 捕获的异常对象

**返回值**: `CommonResult<String>` - 统一响应结果，泛型为String类型

**实现逻辑**:
1. 记录错误日志：
   - 使用`log.error()`记录异常信息
   - 日志格式：`"system error:{}"`，参数为`ex.getMessage()`
   - 同时记录完整的异常堆栈信息（通过第三个参数`ex`）
2. 创建错误响应：
   - 调用`CommonResult.error(ResultCode.FAIL)`创建错误响应
   - 使用`ResultCode.FAIL`作为错误码（500, "system error!"）
3. 设置异常消息：
   - 调用`result.setData(ex.getMessage())`将异常消息设置到响应数据的data字段
4. 返回响应结果

**完整实现代码**:
```java
@ExceptionHandler(value = {Exception.class})
public CommonResult<String> handleException(HttpServletRequest request, Exception ex) {
    log.error("system error:{}", ex.getMessage(), ex);
    CommonResult<String> result = CommonResult.error(ResultCode.FAIL);
    result.setData(ex.getMessage());
    return result;
}
```

**异常处理范围**:
- 捕获所有`Exception`类型及其子类的异常
- 包括但不限于：`RuntimeException`、`IllegalArgumentException`、`NullPointerException`、`IOException`等

**响应格式**:
```json
{
    "code": 500,
    "message": "system error!",
    "data": "具体的异常消息"
}
```

**使用场景**:
- Controller层方法抛出任何异常时，都会被此方法捕获
- 确保所有异常都能返回统一的响应格式
- 避免异常信息直接暴露给客户端

## 3. 异常处理流程

### 3.1 异常处理流程图

```
Controller方法执行
    ↓
抛出异常（Exception）
    ↓
@ControllerAdvice拦截
    ↓
GlobalExceptionHandle.handleException()
    ↓
记录错误日志（log.error）
    ↓
创建CommonResult.error(ResultCode.FAIL)
    ↓
设置异常消息到data字段
    ↓
返回CommonResult<String>
    ↓
Spring序列化为JSON响应
    ↓
客户端收到统一格式的错误响应
```

### 3.2 异常处理示例

#### 示例1：Controller抛出RuntimeException

**Controller代码**:
```java
@RestController
public class TestController {
    @GetMapping("/test")
    public CommonResult<String> test() {
        throw new RuntimeException("测试异常");
    }
}
```

**处理流程**:
1. Controller方法抛出`RuntimeException("测试异常")`
2. `GlobalExceptionHandle.handleException()`捕获异常
3. 记录日志：`log.error("system error:测试异常", exception)`
4. 创建响应：`CommonResult.error(ResultCode.FAIL)` → `{code: 500, message: "system error!"}`
5. 设置异常消息：`result.setData("测试异常")`
6. 返回响应：`{code: 500, message: "system error!", data: "测试异常"}`

**客户端收到的JSON响应**:
```json
{
    "code": 500,
    "message": "system error!",
    "data": "测试异常"
}
```

#### 示例2：Controller抛出IllegalArgumentException

**Controller代码**:
```java
@RestController
public class TestController {
    @PostMapping("/user")
    public CommonResult<User> createUser(@RequestBody User user) {
        if (user == null) {
            throw new IllegalArgumentException("用户信息不能为空");
        }
        // ... 业务逻辑
    }
}
```

**处理流程**:
1. Controller方法抛出`IllegalArgumentException("用户信息不能为空")`
2. `GlobalExceptionHandle.handleException()`捕获异常
3. 记录日志：`log.error("system error:用户信息不能为空", exception)`
4. 创建响应：`CommonResult.error(ResultCode.FAIL)` → `{code: 500, message: "system error!"}`
5. 设置异常消息：`result.setData("用户信息不能为空")`
6. 返回响应：`{code: 500, message: "system error!", data: "用户信息不能为空"}`

**客户端收到的JSON响应**:
```json
{
    "code": 500,
    "message": "system error!",
    "data": "用户信息不能为空"
}
```

## 6. 使用指南

### 6.1 Controller层使用

**正常返回**:
```java
@RestController
public class UserController {
    @GetMapping("/user/{id}")
    public CommonResult<User> getUser(@PathVariable String id) {
        User user = userService.getUser(id);
        return CommonResult.success(user);
    }
}
```

**抛出异常**:
```java
@RestController
public class UserController {
    @PostMapping("/user")
    public CommonResult<String> createUser(@RequestBody User user) {
        // 业务逻辑中抛出异常
        if (user == null) {
            throw new IllegalArgumentException("用户信息不能为空");
        }
        // ... 其他业务逻辑
        return CommonResult.success("创建成功");
    }
}
```

**说明**: Controller方法抛出任何异常都会被`GlobalExceptionHandle`自动捕获并处理。

### 6.2 Service层使用

**Service层可以抛出异常**:
```java
@Service
public class UserService {
    public User getUser(String id) {
        if (id == null || id.isEmpty()) {
            throw new IllegalArgumentException("用户ID不能为空");
        }
        // ... 业务逻辑
    }
}
```

**说明**: Service层抛出的异常会向上传播到Controller层，最终被`GlobalExceptionHandle`捕获。

### 6.3 手动创建错误响应

**使用ResultCode枚举**:

## 7. 设计原则与注意事项

### 7.1 设计原则

1. **统一响应格式**：所有异常都返回统一的`CommonResult`格式
2. **全局异常捕获**：使用`@ControllerAdvice`确保所有Controller异常都被捕获
3. **错误日志记录**：所有异常都记录详细的错误日志，包括堆栈信息
4. **异常消息封装**：将异常消息封装到响应的data字段，便于客户端获取

### 7.2 注意事项

1. **异常类型**：当前实现捕获所有`Exception`类型，包括`RuntimeException`、`CheckedException`等
2. **异常消息**：异常消息通过`ex.getMessage()`获取，如果为null则data字段为null
3. **日志记录**：使用ERROR级别记录所有异常，确保重要异常能被及时发现
4. **响应格式**：所有异常响应都使用`ResultCode.FAIL`（500）作为错误码
5. **HttpServletRequest参数**：虽然方法签名中包含`HttpServletRequest`参数，但当前实现中未使用

### 7.3 扩展建议

如果需要更细粒度的异常处理，可以考虑：

1. **分类异常处理**：
   - 添加`@ExceptionHandler(IllegalArgumentException.class)`处理参数异常
   - 添加`@ExceptionHandler(NullPointerException.class)`处理空指针异常
   - 添加`@ExceptionHandler(IOException.class)`处理IO异常

2. **业务异常类**：
   - 创建`BusinessException`类用于业务异常
   - 添加`@ExceptionHandler(BusinessException.class)`专门处理业务异常

3. **HTTP状态码映射**：
   - 根据异常类型返回不同的HTTP状态码
   - 参数异常返回400，权限异常返回403等

```java
package com.huawei.browsergateway.exception;

import com.huawei.browsergateway.entity.CommonResult;
import com.huawei.browsergateway.entity.ResultCode;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;
import org.springframework.web.bind.annotation.ExceptionHandler;

import javax.servlet.http.HttpServletRequest;

@ControllerAdvice
public class GlobalExceptionHandle {
    private static final Logger log = LogManager.getLogger(GlobalExceptionHandle.class);
    
    @ExceptionHandler(value = {Exception.class})
    public CommonResult<String> handleException(HttpServletRequest request, Exception ex) {
        log.error("system error:{}", ex.getMessage(), ex);
        CommonResult<String> result = CommonResult.error(ResultCode.FAIL);
        result.setData(ex.getMessage());
        return result;
    }
}
```

### 9.2 CommonResult.java

```java
package com.huawei.browsergateway.entity;

/**
 * 通用响应结果
 */
public class CommonResult<T> {
    /**
     * 状态码 (默认 SUCCESS = 200)
     */
    private int code;

    /**
     * 响应消息 (默认 SUCCESS_MSG = "成功")
     */
    private String message;

    /**
     * 响应数据
     */
    private T data;

    /**
     * 默认成功响应构造方法
     */
    private CommonResult() {
        this.code = ResultCode.SUCCESS.getCode();
        this.message = ResultCode.SUCCESS.getMessage();
    }

    /**
     * 成功响应构造方法 (带数据)
     *
     * @param data 返回数据
     */
    private CommonResult(T data) {
        this.code = ResultCode.SUCCESS.getCode();
        this.message = ResultCode.SUCCESS.getMessage();
        this.data = data;
    }

    /**
     * 失败响应构造方法 (带错误代码和消息)
     *
     * @param code    错误码
     * @param message 错误信息
     */
    private CommonResult(int code, String message) {
        this.code = code;
        this.message = message;
    }

    /**
     * 成功响应
     *
     * @param <T> 泛型
     * @return 公共结果
     */
    public static <T> CommonResult<T> success() {
        return new CommonResult<>();
    }

    /**
     * 成功响应 (带数据)
     *
     * @param data 返回数据
     * @param <T>  泛型
     * @return 公共结果
     */
    public static <T> CommonResult<T> success(T data) {
        return new CommonResult<>(data);
    }

    /**
     * 失败响应
     *
     * @param code    错误码
     * @param message 错误信息
     * @param <T>     泛型
     * @return 公共结果
     */
    public static <T> CommonResult<T> error(int code, String message) {
        return new CommonResult<>(code, message);
    }

    /**
     * 失败响应
     *
     * @param errorCode 错误码枚举
     * @param <T>     泛型
     * @return 公共结果
     */
    public static <T> CommonResult<T> error(ResultCode errorCode) {
        return new CommonResult<>(errorCode.getCode(), errorCode.getMessage());
    }

    // Getter and Setter
    public int getCode() {
        return code;
    }

    public void setCode(int code) {
        this.code = code;
    }

    public String getMessage() {
        return message;
    }

    public void setMessage(String message) {
        this.message = message;
    }

    public T getData() {
        return data;
    }

    public void setData(T data) {
        this.data = data;
    }

    @Override
    public String toString() {
        return "CommonResult{" +
                "code=" + code +
                ", message='" + message + '\'' +
                ", data=" + data +
                '}';
    }
}
```
