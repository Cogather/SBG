## 1. 根包工具类

### 1.1 HttpUtil

**文件路径**: `util/HttpUtil.java`

**作用**: HTTP请求工具类，提供HTTP客户端连接池管理和HTTP请求发送功能。

**类设计**:
- **类型**: 工具类（静态方法）
- **线程安全**: 是（使用连接池，线程安全）

**依赖库**:
- `org.apache.hc.client5.http` - Apache HttpClient 5.x
- `cn.hutool` - Hutool工具库

**核心字段**:

| 字段名 | 类型 | 访问修饰符 | 说明 |
|--------|------|-----------|------|
| `httpClient` | `CloseableHttpClient` | `private static final` | HTTP客户端实例（通过getter暴露） |
| `connectionManager` | `PoolingHttpClientConnectionManager` | `private static final` | 连接池管理器 |

**连接池配置**:
- 最大总连接数: 100
- 每个路由最大连接数: 20
- 空闲连接清理时间: 1分钟

**静态初始化块**:
```java
static {
    connectionManager = new PoolingHttpClientConnectionManager();
    connectionManager.setMaxTotal(100);
    connectionManager.setDefaultMaxPerRoute(20);
    httpClient = HttpClients.custom()
            .setConnectionManager(connectionManager)
            .evictIdleConnections(TimeValue.ofMinutes(1))
            .build();
}
```

**方法定义**:

#### 1.1.1 request(String url, String method, String body)

**功能**: 发送HTTP请求（无返回值）

**参数**:
- `url` (String): 请求URL
- `method` (String): HTTP方法（GET、POST等）
- `body` (String): 请求体，可为空

**返回值**: `void`

**异常处理**:
- 如果响应码不是200，记录警告日志
- 如果发生IOException，记录错误日志并抛出RuntimeException

**实现逻辑**:
1. 使用`ClassicHttpRequests.create(method, url)`创建请求
2. 如果body不为空，设置请求体为StringEntity
3. 执行请求，检查响应码
4. 响应码非200时记录警告日志

#### 1.1.2 request(String url, String method, String body, TypeReference<T> typeReference)

**功能**: 发送HTTP请求并返回解析后的对象

**参数**:
- `url` (String): 请求URL
- `method` (String): HTTP方法
- `body` (String): 请求体，可为空
- `typeReference` (TypeReference<T>): 返回类型引用

**返回值**: `T` - 解析后的对象，如果响应码非200或实体为空则返回null

**异常处理**:
- 如果响应码不是200，记录警告日志并返回null
- 如果发生IOException，记录错误日志并抛出RuntimeException

**实现逻辑**:
1. 创建HTTP请求
2. 如果body不为空，设置请求体
3. 执行请求，检查响应码
4. 如果响应码为200且实体不为空，使用JSONUtil解析响应体为指定类型
5. 返回解析后的对象

**使用示例**:
```java
// 无返回值请求
HttpUtil.request("http://example.com/api", "POST", "{\"key\":\"value\"}");

// 有返回值请求
TypeReference<Map<String, Object>> typeRef = new TypeReference<Map<String, Object>>() {};
Map<String, Object> result = HttpUtil.request("http://example.com/api", "GET", null, typeRef);
```

**方法定义**:

#### 1.2.1 compressJson(String sourceJsonPath, String targetZstPath)

**功能**: 压缩JSON文件为Zstd格式

**参数**:
- `sourceJsonPath` (String): 源JSON文件路径
- `targetZstPath` (String): 压缩后的.zst文件路径

**返回值**: `boolean` - 压缩是否成功

**验证逻辑**:
1. 检查源文件是否存在且为文件
2. 检查源文件扩展名是否为.json（不区分大小写）

**实现逻辑**:
1. 验证源文件有效性
2. 使用FileInputStream读取源文件
3. 使用FileOutputStream创建目标文件
4. 使用ZstdOutputStream（压缩级别6）进行压缩
5. 使用8KB缓冲区逐块复制数据
6. 自动关闭所有流（try-with-resources）

**异常处理**:
- 文件不存在或不是文件：记录错误日志，返回false
- 文件扩展名不是.json：记录错误日志，返回false
- IOException：打印错误信息到System.err，返回false

#### 1.2.2 decompressJson(String sourceZstPath, String targetJsonPath)

**功能**: 解压Zstd压缩的JSON文件

**参数**:
- `sourceZstPath` (String): 源.zst压缩文件路径
- `targetJsonPath` (String): 解压后的JSON文件路径

**返回值**: `boolean` - 解压是否成功

**验证逻辑**:
1. 检查源文件是否存在且为文件

**实现逻辑**:
1. 验证源文件有效性
2. 使用FileInputStream读取压缩文件
3. 使用ZstdInputStream解压
4. 使用FileOutputStream写入目标文件
5. 使用8KB缓冲区逐块复制数据
6. 自动关闭所有流（try-with-resources）

**异常处理**:
- 文件不存在或不是文件：记录错误日志，返回false
- IOException：打印错误信息到System.err，返回false

**使用示例**:
```java
// 压缩JSON文件
boolean success = ZstdUtil.compressJson("userdata.json", "userdata.json.zst");

// 解压Zstd文件
boolean success = ZstdUtil.decompressJson("userdata.json.zst", "userdata.json");
```

### 1.3 UserdataSlimmer

**文件路径**: `util/UserdataSlimmer.java`

**作用**: 用户数据脱敏工具类，对浏览器用户数据（cookies和localStorage）进行智能过滤和脱敏处理。

**类设计**:
- **类型**: 工具类（静态方法）
- **线程安全**: 是（无共享状态）

**依赖库**:
- `cn.hutool` - Hutool工具库
- `org.apache.logging.log4j` - Log4j日志

**常量定义**:

| 常量名 | 类型 | 值 | 说明 |
|--------|------|-----|------|
| `LOGIN_KEYWORDS` | `List<String>` | ["session", "token", "auth", "login", "user", "sid", "uid", "account", "access", "refresh", "credential", "ticket", "sign", "key"] | 登录凭证关键词 |
| `VERIFY_KEYWORDS` | `List<String>` | ["verify", "captcha", "check", "pass", "valid", "certify", "robot", "human", "anti", "shield", "audit"] | 验证相关关键词 |
| `VERIFY_PASSED_VALUES` | `List<String>` | ["passed", "true", "success", "valid", "1", "yes", "allowed"] | 验证通过的值 |
| `MUEN_APP_FLAG` | `String` | "tmofamily.com" | 沐恩自研应用标识 |

**方法定义**:

#### 1.3.1 slimInplace(File file)

**功能**: 对用户数据文件进行原地脱敏处理

**参数**:
- `file` (File): 要处理的用户数据JSON文件

**返回值**: `void`

**异常处理**:
- 文件不存在：记录错误日志，抛出RuntimeException

**实现逻辑**:
1. 记录开始时间
2. 验证文件存在性
3. 读取原始JSON内容（UTF-8编码）
4. 解析为JSONObject
5. 提取cookies和origins数组（如果不存在则创建空数组）
6. 调用slimCookies处理cookies
7. 调用slimOrigins处理origins
8. 构建新的JSON对象，只包含处理后的cookies和origins
9. 将JSON压缩（去除所有空白字符）
10. 写回原文件
11. 记录处理耗时和统计信息（cookies数量、origins数量、文件大小变化）

**日志输出格式**:
```
slim user data success, cost:{耗时}ms. cookies: {原始数量} -> {处理后数量}; origins: {原始数量} -> {处理后数量}; size(KB): {原始大小} -> {处理后大小}
```

#### 1.3.2 slimCookies(JSONArray originalCookies)

**功能**: 过滤和脱敏Cookies数组（私有方法）

**参数**:
- `originalCookies` (JSONArray): 原始Cookies数组

**返回值**: `JSONArray` - 处理后的Cookies数组

**过滤规则**:
1. **沐恩应用保留**: domain包含"tmofamily.com"的cookie直接保留
2. **过期检查**: 如果cookie有expires字段且不为null，检查是否过期（expires > 当前时间戳）
3. **空值过滤**: value为空或长度<=1的cookie被过滤
4. **关键词保留**: cookie的name（转小写）包含LOGIN_KEYWORDS中任一关键词的保留
5. **HttpOnly保留**: httpOnly为true的cookie保留

**实现逻辑**:
1. 如果数组为空，返回空数组
2. 获取当前时间戳（秒级）
3. 遍历每个cookie对象
4. 应用上述过滤规则
5. 符合条件的cookie添加到结果数组

#### 1.3.3 slimOrigins(JSONArray originalOrigins)

**功能**: 过滤和脱敏Origins数组（私有方法）

**参数**:
- `originalOrigins` (JSONArray): 原始Origins数组

**返回值**: `JSONArray` - 处理后的Origins数组

**过滤规则**:
1. **沐恩应用保留**: origin包含"tmofamily.com"的origin直接保留
2. **localStorage处理**: 对每个origin的localStorage调用slimLocalStorage处理
3. **空数组过滤**: 如果处理后的localStorage为空，该origin不保留

**实现逻辑**:
1. 如果数组为空，返回空数组
2. 获取当前时间戳
3. 遍历每个origin对象
4. 应用沐恩应用保留规则
5. 提取localStorage数组（如果不存在则创建空数组）
6. 调用slimLocalStorage处理
7. 如果处理后的localStorage不为空，构建新的origin对象并添加到结果

#### 1.3.4 slimLocalStorage(String origin, JSONArray originalLocal, long currentTimestamp)

**功能**: 过滤和脱敏localStorage数组（私有方法）

**参数**:
- `origin` (String): 源域名
- `originalLocal` (JSONArray): 原始localStorage数组
- `currentTimestamp` (long): 当前时间戳（秒级）

**返回值**: `JSONArray` - 处理后的localStorage数组

**过滤规则**:
1. **空值过滤**: value为空或长度<=1的项被过滤
2. **关键词匹配**: name（转小写）包含ALL_KEYWORDS中任一关键词的保留
3. **TikTok特殊处理**: 如果origin包含".tiktok.com"，且name包含"text"，则过滤掉
4. **验证通过值**: value（转小写）等于VERIFY_PASSED_VALUES中任一值的保留
5. **过期检查**: 如果value是JSON格式，检查其中的expire或expires字段，如果过期则过滤

**实现逻辑**:
1. 如果数组为空，返回空数组
2. 遍历每个localStorage项
3. 提取name和value（都转小写）
4. 应用空值过滤
5. 检查关键词匹配
6. 应用TikTok特殊规则
7. 检查验证通过值
8. 解析JSON格式的value，检查过期时间
9. 符合条件的项添加到结果数组

#### 1.3.5 getArraySize(JSONArray array)

**功能**: 获取数组大小（私有辅助方法）

**参数**:
- `array` (JSONArray): JSON数组

**返回值**: `int` - 数组大小，如果为null则返回0

**使用示例**:

#### 1.7.6 writeAuditLog(AuditType, AuditLogInfo, AuditLevel, OperateType, AuditResult)

**功能**: 写入审计日志

**参数**:
- `auditType` (AuditType): 审计类型（操作/安全）
- `auditLogInfo` (AuditLogInfo): 审计日志信息
- `level` (AuditLevel): 日志级别（可为null，默认MINOR）
- `operateType` (OperateType): 操作类型（可为null，默认UPHOLD）
- `result` (AuditResult): 操作结果（可为null，默认SUCCESSFUL）

**返回值**: `void`

**实现逻辑**:
1. 根据auditType选择日志路径（操作日志或安全日志）
2. 构建JSON请求体，包含以下字段：
   - operation: 操作名称
   - level: 日志级别代码（默认1）
   - userName: 用户名
   - dateTime: 当前时间戳（毫秒）
   - appId: 0
   - appName: "browsergw"
   - terminal: 终端IP
   - serviceName: "browsergw"
   - result: 结果代码（默认0）
   - detail: 详细信息
   - detail_zh: 详细信息（中文）
   - operateType: 操作类型代码（仅操作日志，默认6）
3. 如果路径使用cse://协议且CSP SDK不可用，跳过记录
4. 使用RestTemplate发送POST请求

### 2.1 Tlv

**文件路径**: `util/encode/Tlv.java`

**作用**: TLV数据结构类，表示Tag-Length-Value格式的数据结构。

**类设计**:

**字段定义**:

| 字段名 | 类型 | 访问修饰符 | 说明 |
|--------|------|-----------|------|
| `magic` | `short` | `private` | 魔数 |
| `count` | `int` | `private` | 字段个数 |
| `len` | `int` | `private` | 总长度（所有字段的Type+Len+Data总长度） |
| `fields` | `List<TlvField>` | `private` | TLV字段列表 |

#### 2.1.1 getType()

2. 查找type等于ID.TYPE的字段
3. 返回该字段的int值

#### 2.1.2 marshal(ByteOrder)

**功能**: 序列化TLV结构为字节数组

**参数**:
- `order` (ByteOrder): 字节序（大端/小端）

**返回值**: `byte[]` - 序列化后的字节数组

**序列化格式**:
1. **魔数** (2字节): short类型，使用指定字节序
2. **字段数量** (4字节): int类型，使用指定字节序
3. **总长度** (4字节): int类型，使用指定字节序
4. **字段列表** (变长):
   - 每个字段包含：
     - Type (4字节): int类型，使用指定字节序
     - Length (4字节): int类型，使用指定字节序
     - Data (变长): 字段数据

**实现逻辑**:
1. 设置magic为MAGIC常量
2. 创建ByteArrayOutputStream
3. 写入魔数（使用writeShort）
4. 写入字段数量（使用writeInt）
5. 写入总长度（使用writeInt）
6. 遍历fields列表，对每个字段：
   - 写入Type（使用writeInt）
   - 写入Length（使用writeInt）
   - 写入Data（使用writeAndCheckSize）
7. 返回字节数组

#### 2.1.8 readAndCheckSize(InputStream, byte[])（私有方法）

**功能**: 读取数据并检查读取长度

**参数**:
- `in` (InputStream): 输入流
- `buffer` (byte[]): 缓冲区

**返回值**: `void`

**异常处理**:
- 如果读取长度不足，抛出IOException

**实现逻辑**:
1. 循环读取直到缓冲区填满

**依赖库**:

- `java.nio.ByteBuffer` - 字节缓冲区
- `java.nio.ByteOrder` - 字节序

**方法定义**:

#### 2.2.1 marshal(Object)

**功能**: 将Java对象转换为TLV结构

**参数**:
- `obj` (Object): 要转换的Java对象

**返回值**: `Tlv` - 转换后的TLV结构

**异常处理**:
- 如果对象是基本类型或包装类型，抛出IllegalArgumentException
- 如果字段类型不匹配，抛出IllegalArgumentException
- 其他异常抛出Exception

**实现逻辑**:
1. 获取对象的Class
2. 检查是否为基本类型或包装类型，如果是则抛出异常
3. 创建Tlv对象
4. 遍历对象的所有声明字段：
   - 检查字段是否有@TlvTag注解
   - 如果没有注解，跳过
   - 设置字段可访问（field.setAccessible(true)）
   - 获取字段值
   - 调用fieldToBytes将字段值转换为字节数组
   - 创建TlvField并添加到列表
5. 设置TLV的count和fields
6. 计算总长度：每个字段的Type(4) + Len(4) + Data长度
7. 设置TLV的len
8. 返回TLV对象

#### 2.2.2 unmarshal(Tlv, Object)

**功能**: 将TLV结构解析到Java对象中

**参数**:
- `tlv` (Tlv): TLV结构
- `obj` (Object): 要填充的Java对象

**返回值**: `void`

**异常处理**:
- 如果目标对象为null，抛出IllegalArgumentException
- 如果字段类型不匹配或数据长度无效，抛出IllegalArgumentException
- 其他异常抛出Exception

**实现逻辑**:
1. 验证目标对象不为null
2. 获取对象的Class
3. 构建字段映射（按Type索引），加速查找
4. 遍历对象的所有声明字段：
   - 检查字段是否有@TlvTag注解
   - 如果没有注解，跳过
   - 根据tag.id在映射中查找对应的TlvField
   - 如果找不到，跳过
   - 设置字段可访问
   - 调用setFieldValue设置字段值
5. 完成解析

#### 2.2.3 fieldToBytes(Object, String, String)（私有方法）

**功能**: 将字段值转换为字节数组

**参数**:
- `value` (Object): 字段值
- `fieldType` (String): 字段类型（string/int32/int64/bytes）
- `fieldName` (String): 字段名称（用于错误信息）

**返回值**: `byte[]` - 转换后的字节数组

**异常处理**:
- 如果value为null，返回空字节数组
- 如果类型不匹配，抛出IllegalArgumentException

**支持的类型**:
- **string**: String类型，使用默认字符集转换为字节数组
- **int32**: Integer类型，使用大端序转换为4字节数组
- **int64**: Long类型，使用大端序转换为8字节数组
- **bytes**: byte[]类型，克隆数组返回

**实现逻辑**:
1. 如果value为null，返回空字节数组
2. 根据fieldType进行switch分支：
   - string: 检查类型，转换为字节数组
   - int32: 检查类型，使用ByteBuffer（大端序）转换为4字节
   - int64: 检查类型，使用ByteBuffer（大端序）转换为8字节
   - bytes: 检查类型，克隆数组
   - 其他: 抛出异常

#### 2.2.4 setFieldValue(Object, Field, byte[], String)（私有方法）

**功能**: 根据字节数组设置字段值

**参数**:

- `field` (Field): 字段对象
- `data` (byte[]): 字节数组

**返回值**: `void`

**异常处理**:
- 如果数据长度无效，抛出IllegalArgumentException
- 如果类型不支持，抛出IllegalArgumentException

**实现逻辑**:
1. 根据fieldType进行switch分支：
   - string: 使用默认字符集转换为String，设置字段值
   - int32: 检查长度必须为4，使用ByteBuffer（大端序）解析为int，设置字段值
   - int64: 检查长度必须为8，使用ByteBuffer（大端序）解析为long，设置字段值
   - bytes: 克隆字节数组，设置字段值
   - 其他: 抛出异常

#### 2.3.2 encode(ChannelHandlerContext, Object, ByteBuf)

**功能**: 编码消息为字节流

**参数**:
- `ctx` (ChannelHandlerContext): Netty通道上下文
- `msg` (Object): 要编码的消息（可以是byte[]或Java对象）
- `out` (ByteBuf): 输出字节缓冲区

**返回值**: `void`

**异常处理**:

**实现逻辑**:
1. 从通道上下文获取Client对象
2. 从Client获取sessionID、appType、clientIP
3. 判断消息类型：
   - 如果是byte[]：

     - 使用TlvCodec.marshal将对象转换为TLV
     - 使用tlv.marshal(ByteOrder.BIG_ENDIAN)序列化为字节数组
     - 记录数据大小和流量速率
     - 写入ByteBuf

**使用示例**:
```java

```

### 2.4 TlvDecoder

**文件路径**: `util/encode/TlvDecoder.java`

**作用**: TLV解码器（Netty），将字节流解码为TLV结构。

**类设计**:
- **类型**: Netty解码器（继承ByteToMessageDecoder）
- **线程安全**: 是（Netty框架保证）

**依赖库**:
- `io.netty.buffer.ByteBuf` - Netty字节缓冲区
- `io.netty.channel.ChannelHandlerContext` - Netty通道上下文
- `io.netty.handler.codec.ByteToMessageDecoder` - Netty解码器基类
- `com.huawei.browsergateway.tcpserver.Client` - 客户端类
- `com.huawei.browsergateway.tcpserver.FlowRateTracker` - 流量速率跟踪器

**常量定义**:

| 常量名 | 类型 | 值 | 说明 |
|--------|------|-----|------|
| `MIN_SIZE` | `int` | 10 | 最小数据长度（magic(2) + count(4) + dataLen(4)） |
| `HEADER_TAG` | `short` | 28021 | 头部魔数 |

**字段定义**:

| 字段名 | 类型 | 访问修饰符 | 说明 |
|--------|------|-----------|------|
| `maxLen` | `int` | `private final` | 单个字段最大长度限制 |
| `flowRateTracker` | `FlowRateTracker` | `private final` | 流量速率跟踪器 |
| `serviceType` | `String` | `private final` | 服务类型 |

**构造方法**:

#### 2.4.1 TlvDecoder(int, FlowRateTracker, String)

**参数**:
- `maxLen` (int): 单个字段最大长度限制
- `flowRateTracker` (FlowRateTracker): 流量速率跟踪器
- `serviceType` (String): 服务类型

**方法定义**:

#### 2.4.2 decode(ChannelHandlerContext, ByteBuf, List<Object>)

**功能**: 解码字节流为TLV对象

**参数**:
- `ctx` (ChannelHandlerContext): Netty通道上下文
- `in` (ByteBuf): 输入字节缓冲区
- `out` (List<Object>): 输出对象列表

**返回值**: `void`

**异常处理**:
- 如果数据格式错误，抛出IllegalArgumentException
- 如果发生其他异常，重置读取位置，不抛出异常（等待更多数据）

**解码逻辑**:
1. **检查最小长度**: 如果可读字节数 < MIN_SIZE(10)，返回等待
2. **标记读取位置**: 使用markReaderIndex标记
3. **读取魔数**: 读取2字节short，如果不是HEADER_TAG，重置并跳过一个字节，返回
4. **读取字段数量**: 读取4字节int
5. **读取总长度**: 读取4字节int
6. **检查数据完整性**: 如果可读字节数 < dataLen，重置等待
7. **设置TLV头部**: 设置magic、count、len
8. **解析字段列表**:
   - 循环count次：
     - 检查是否有8字节（Type+Len）
     - 读取Type（4字节int）
     - 读取Length（4字节int）
     - 验证Length：不能为负数，不能超过maxLen
     - 检查是否有足够字节读取Value
     - 读取Value（len字节）
     - 创建TlvField并添加到TLV
9. **记录流量**: 从Client获取sessionId，记录总字节数
10. **添加到输出**: 将解析成功的TLV添加到out列表

**使用示例**:
```java
FlowRateTracker flowTracker = new FlowRateTracker();
TlvDecoder decoder = new TlvDecoder(1024 * 1024, flowTracker, "control");

// 在Netty pipeline中使用
pipeline.addLast("tlvDecoder", decoder);
```

## 4. 注意事项

1. **线程安全**: 
   - 大部分工具类都是线程安全的（静态方法，无共享状态）
   - `Tlv`、`TlvField`、`Message`等数据类非线程安全，每个线程应使用独立实例

2. **异常处理**:
   - `HttpUtil` 在发生IOException时会抛出RuntimeException
   - `ZstdUtil` 在发生异常时返回false，不抛出异常
   - `UserdataSlimmer` 在文件不存在时抛出RuntimeException
   - `TlvCodec` 在类型不匹配时抛出IllegalArgumentException

3. **资源管理**:
   - `HttpUtil` 使用连接池，无需手动关闭
   - `ZstdUtil` 和 `GzipUtil` 使用try-with-resources自动关闭流
   - `TlvEncoder` 和 `TlvDecoder` 由Netty框架管理生命周期

4. **字节序**:
   - TLV编解码默认使用大端序（BIG_ENDIAN）
   - 所有整数类型（int、long、short）都使用大端序

5. **字段类型**:
   - TLV字段类型支持：string、int32、int64、bytes
   - string类型使用默认字符集（UTF-8）
   - int32和int64使用大端序

6. **数据验证**:
   - `TlvDecoder` 会验证字段长度，不能为负数，不能超过maxLen
   - `TlvCodec` 会验证字段类型是否匹配
   - `GzipUtil` 会进行路径穿越攻击检测

7. **依赖注入**:
   - `DeployUtil` 需要Spring容器注入SystemUtilAdapter
   - 使用前确保Spring容器已初始化

8. **日志记录**:
   - 所有工具类都使用日志记录重要操作和错误
   - 日志级别：INFO（正常操作）、WARN（警告）、ERROR（错误）
