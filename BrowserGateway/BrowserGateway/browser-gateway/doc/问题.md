1. 如果没有明确的约束，代码比较容易跑飞，写很多没有用到的逻辑
2. 当一个服务的代码量变多后，准确性和生成效率会明显降低
3. AI写的代码过多，遇到问题定位很困难

解决方案
1. 先建立测试工程，用于验证和拦截基本的功能
2. 需要定义好模块功能定位与接口：接口必须要明确详细的接口参数、url等
3. 先plan 再执行
4. 设计文档中，最好把代码仓的目录结构划分、模块划分拆分明确，避免出现agent自由理解自由生成的情况

模块拆分原则：
1. 自底向上：先完成基础层和适配层，再考虑核心业务层
2. 核心业务层各模块解耦，支持独立实现、模块间需要接口契约文档验证/约束与其他模块的依赖
3. 接口契约文档需要包含什么东西
4. 模块设计文档的格式和要求

要做森么：
1. 文档内容整理
2. 刷新adapter适配层
3. 代码内容：补充注释、适当重构
