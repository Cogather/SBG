# 蓝区重写实践 - 配图说明与豆包生成 Prompt

> 参考得物技术《Spec Coding 项目实战》(https://mp.weixin.qq.com/s/1Oi7YhMgcPp9gQAWPndXWA) 常见图类型，为《蓝区重写实践》文档整理可复用图及豆包生成用 Prompt。链接若无法打开，可仅按下列 Prompt 生成风格一致的配图。

---

## 一、得物文中常见可复用图类型（对应到本实践）

| 得物文中的图类型 | 在本实践中的用途 | 建议放置位置 |
|------------------|------------------|--------------|
| 内网 vs 外网/多环境架构对比 | 内网 vs 蓝区架构对比，同一套业务、两套底座 | 第二章 CSP 适配层后 |
| 开发/实施时间线（七阶段横向或纵向） | 文档梳理 → 适配层抽象 → 测试用例生成 → 代码实现 → 测试工程搭建与功能调测 → 部署验证与调测 | 第三章开发场景前或内 |
| 规范/体系三层结构图 | 约束层、示范层、执行层（或 SDD/TDD/清单） | 第四章思考中 |
| 开发案例卡片或 2×2 矩阵 | 三个开发案例的示意卡片 | 第三章案例后 |
| 能力边界/范围对比（左右分块或 Venn） | 蓝区可验证 vs 不可验证 | 第四章可验证与不可验证 |
| 工具/客户端与主服务关系图 | 测试工程 ↔ BrowserGateway（蓝区） | 第三章或第四章 |

## 二、豆包生成图 Prompt（按图逐一）

### 图1：内网 vs 蓝区架构对比

**Prompt：**

```
画一张技术架构对比图，左右分栏，风格简洁、适合技术文章插图。
左侧标题「内网」：从上到下三层，最上是「BrowserGateway 应用层」，中间是「CSP 适配层」，最下是「CSP SDK + 完整依赖（CSE、证书中心、告警平台等）」，用箭头向下连接，标注「强依赖」。
右侧标题「蓝区」：同样三层，最上是「BrowserGateway 应用层」，中间是「CSP 适配层」，最下是「Custom 实现（日志、本地证书、内存端点等）」，用箭头向下连接，标注「可替换、无 CSP」。
底部居中一行小字：「同一套业务代码，两套底座，配置切换」。整体偏线框图、蓝灰配色，不要 3D 和卡通。
```

### 图2：七阶段实施时间线

**Prompt：**

```
画一张横向时间线图，适合技术实践文章，扁平简洁。
从左到右七个阶段，用箭头串联：
阶段一「依赖梳理与设计」→ 阶段二「文档梳理」→ 阶段三「适配层抽象」→ 阶段四「测试用例生成」→ 阶段五「代码实现」→ 阶段六「测试工程搭建与功能调测」→ 阶段七「部署验证与调测」。
每个阶段下方一行小字产出（可选）：需求与接口清单 / 架构与模块文档、接口与双实现设计 / 用例与 Mock 策略、Csp* 与 Custom* 实现 / 独立测试工程与蓝区调测、可验证清单与黄区部署验证。
整体蓝灰色、线框风格，可带简单图标（文档、抽象、用例、代码、测试、部署），不要花哨。
```

### 图3：SDD + TDD 流程闭环

**Prompt：**

```
画一张流程图，展示「规格 → 实现 → 测试」闭环，适合技术文档。
三个主块呈环形箭头连接：左侧「SDD 规格（架构设计、模块设计、接口契约）」→ 下方「代码实现（含 AI 参与）」→ 右侧「TDD 验证（蓝区本地功能测试与集成测试）」→ 回到「SDD 规格」。
下方可加一行：蓝区本地功能测试与集成测试，黄区部署集成测试。风格简洁、线框、蓝灰配色，适合文章插图。
```

### 图4：开发案例卡片（2×2 或 3 卡片）

**Prompt：**

```
画三张并排的简约卡片图，适合技术实践文章，每张卡片内部分为三行：
卡片1 标题「适配层与配置切换」：背景 / 依赖 CSP 的能力需抽象；做法 / Csp* 与 Custom* 两套实现、配置切换；结果 / 改配置即切环境。
卡片2 标题「独立测试工程」：背景 / 蓝区无 Docker、无完整 CSP；做法 / REST与TCP/WebSocket 客户端、Mock 数据；结果 / 蓝区可自测协议与 API。
卡片3 标题「蓝区问题定位」：背景 / 部署后起不来；做法 / 查配置与 Custom 适配器、对照清单；结果 / 边界固化、文档沉淀。
风格统一、线框卡片、蓝灰白配色，可带简单图标。
```

### 图5：蓝区可验证 vs 不可验证（左右分块）

**Prompt：**

```
画一张左右分块对比图，适合技术文档。
左侧块标题「蓝区可验证」：列表形式，内容为「REST API（预开、删数据、插件信息等）」「TCP/WebSocket 连接与控制消息、Mock 媒体」「进程启动、端口、配置与适配器切换」，配绿色或勾选示意。
右侧块标题「蓝区不保证/不可验证」：列表形式，内容为「依赖 CSE/真实存储的完整业务流程」「真实浏览器渲染、CSE 会话一致性」「证书中心订阅、告警上台、CSE 注册」，配橙色或叉号示意。
中间用竖线分隔，顶部可写「验证范围边界」。风格简洁、扁平、蓝灰配色。
```

### 图7：规范/指导思想三层（可选，对应得物「约束层、示范层、视觉层」）

**Prompt：**

```
画一张三层结构图，自上而下，适合技术规范说明。
第一层「约束层」：环境与配置约定（adapter.environment、不写死环境）；第二层「示范层」：架构图与接口契约、CSP 适配层设计；第三层「执行层」：可验证/不可验证清单、测试工程与 TDD。
```

## 三、使用说明

- 将上述任一「Prompt」整段复制到豆包（或支持文生图的模型）对话中，即可生成对应风格配图。
- 若豆包支持上传参考图，可先上传得物公众号文章截图（若能打开），再加 Prompt 中「风格参考该图，内容按上述要求」。
- 生成后建议统一裁剪为相同宽高比（如 16:9 或 4:3），便于插入公众号或 Word。
- 图中文字若识别不清，可在排版时用文本框覆盖为中文说明。
